# Fighters Through Time agent context

This file applies to the entire repository. It is the durable orientation document for AI agents working on this project. Keep it synchronized with material architecture or scope changes.

`CLAUDE.md` imports this file and adds the local toolchain (Godot executable locations, verified commands), the `docs/` authority map, and Claude Code configuration. Tool-specific setup belongs there; durable project truth belongs here.

## How to use this context

1. Read this file before changing the project.
2. Read the relevant section of `design-godot.md` before implementing gameplay, content, UI, networking, save, or performance behavior. The design document is the full product and technical specification; this file is a working summary and repository map.
3. Inspect the current scripts, scenes, resources, and `project.godot` before editing. The design document describes the target, while the repository contains a partially implemented prototype.
4. Treat explicit user instructions as highest priority. Otherwise, follow the authority rule below.
5. Clearly distinguish `implemented`, `prototype/placeholder`, `planned`, and `deferred` behavior in plans and handoffs.

### The authority rule (P04, adopted 2026-09-13)

**`design-godot.md` and the adopted contracts under `docs/design-contracts/` define *intended behaviour*. Verified code, `.tres` data and scene bindings at a pinned revision describe the *current build* — they are evidence about that build, not authority to reverse an approved target.**

This inverts the pre-Package-11 rule ("if a document and a `.tres` resource disagree, the resource wins"), which quietly promoted every shipped value into the design. Reading a resource proves its stored value, not that the game loads or applies it correctly.

When the two differ: close it by changing the build, or record it in `docs/design-contracts/DESIGN_BUILD_DEVIATIONS.md` — **the live ledger** — with a stable deviation ID, the intended behaviour and its decision reference, the observed value with its pinned commit and file identifier, an owner (`Unassigned` unless claimed), and concrete acceptance criteria. A deviation does not become the new target merely because it shipped, and a record is retained after closure rather than deleted. Where the design deliberately leaves a number provisional, record that fact rather than inventing a requirement.

**The orthogonal rule survives untouched: never create a second canonical value.** Static tuning still lives in exactly one place — a `.tres`, or a single named rulebook constant — and a factory, UI script or document never holds a second copy. "The resource is not the authority" does not mean "copy the number somewhere else".

## Product identity and non-negotiable pillars

`Fighters Through Time` is a 2D game that combines side-scrolling action-adventure gameplay with a platform-fighter mode. The nine playable characters are historical figures whose exaggerated abilities are manifestations of humanity's collective memory, called Temporal Resonance.

Core design contracts:

- An ability must make sense in both modes. The same move used for Story Mode combat or a puzzle should translate naturally to Fighter Mode.
- Combat uses standard HP, not a Smash-style accumulating knockback percentage. At 0 HP a fighter is knocked out. In Fighter Mode, falling through the bottom blast zone also costs one stock; the sides and top are solid boundaries. Three of the ten stages are **Open** (Paris, Vesuvius, Nassau) — they author real pits, so the bottom blast zone is reachable through ordinary play.
- Story progression and the Temporal Resonance Grid affect Story Mode only. Fighter Mode remains competitively normalized.
- **The hero's Temporal Resonance grows across the campaign. There is no mid-campaign power loss; the charge is surrendered exactly once, by choice, at the very end.** (V7.5, Package 11 A6 — the retired power-fade arc is retired for good. Do not reintroduce a "you're losing your power" beat.)
- **The roster will grow. Never hardcode roster size, and never enumerate the cast in load-bearing ways.** `FTT.Core.CharacterRoster`, backed by `resources/Content/content_manifest.csv`, is the single runtime roster; every production consumer reads it. The one documented exception is `FTT.FighterSim.FighterCharacterID` (see the Roster section).
- **The Act III knowledge boundary:** no dialogue line, brief or UI string may state a Villain's-True-Plan fact before Level 13. `tests/ContentValidation/NarrativeKnowledgeBoundaryTests.cs` is the gate.
- All nine characters are available from the start in the initial build. Character unlocking is a later balance/content phase.
- A campaign save locks the selected character for the whole playthrough; there is no mid-campaign character swapping.
- The initial Fighter Mode scope is 1v1 only: local shared-screen/LAN and online rollback. Four-player free-for-all and 2v2 are post-launch work and must not be added during initial development.
- Delay-based online combat is not acceptable. The intended final online implementation is deterministic GGPO-style rollback.
- Initial builds are English-only but must be localization-ready from day one. User-visible strings use translation keys, not hardcoded English.
- Alternate costumes, cosmetic items, full-match replays, detailed post-match stat sheets, online account/profile systems, and Training Mode are outside the initial scope unless the user explicitly reprioritizes them.

## Narrative and mode context

**The V7.5 canon replaced the Unity-era one wholesale (Package 11 A6, 2026-09-13).** The Apex Archive, the Chrono-Resistance, "the cult", "cultists" and the Library-of-Alexandria overload are **retired vocabulary** — `grep -i "Apex Archive|Chrono-Resistance"` over `localization/en.csv` returns nothing, and it must stay that way.

The **Unbound** are the antagonist faction. Their **First Strike** was aimed at *people, not places*: an extraction beam that takes the pivotal individual out of their moment. **Temporal Resonance is time's self-correcting response** to that theft, which is why the hero has it. The **Wardens** are the player's faction, led by Commander Sarah aboard a Time-Ship that is **cut off**, not hijacked, and that serves as the Story Mode hub. The **Meridian** is the load-bearing thread the campaign restores.

The campaign follows only the player's locked-in historical figure and the Warden crew. Other roster characters appear as **captives** of the First Strike, not as hub NPCs or companions — the `{CaptiveName1}` / `{CaptiveName2}` tokens resolve them at render time. Fighter Mode is narratively framed as sparring in the Time-Ship's Temporal Arena.

`resources/Enemies/chrono_warden.tres` keeps its ID and its "Chrono-Warden" display name deliberately: with the Wardens now the player's faction it reads as **a stolen title, worn mockingly** (the lore note is a comment in the resource). Legacy identifiers are retained everywhere — scene IDs and paths, `CampaignLevel` member names, level IDs, enemy/boss resource IDs (`archive_prime`, `apex_eraser`), ability IDs, `PresentationEventID` strings, atlas paths, pool config IDs, dialogue sequence IDs and **every translation key name**. Only English *values*, the non-localized debug `DisplayName` fields and prose changed.

Locked slots are shown, never hidden (`EventBus.OnAbilitySlotLockChanged`, states `Dormant | Suppressed | Clear`), and the Story Move List badges an unrestored slot with `movelist_dormant_until`. The 975-dust grid economy is untouched.

## Technology and runtime targets

- Engine in the current repository: Godot .NET 4.7.1 (`Godot.NET.Sdk/4.7.1`). The GDD's minimum is Godot 4.4+.
- Language/runtime: C# on .NET 10 (`net10.0`, SDK 10.0.302 pinned by `global.json`). Root namespace: `FTT`. Migrated from .NET 8 on 2026-08-06; Godot 4.7.1 loads the `net10.0` assembly and the full suite passes. `design-godot.md` Section 12 still says .NET 8 — the project file is authoritative.
- Current package/runtime dependencies: `K4os.Compression.LZ4` 1.3.8, Klotho's `Newtonsoft.Json` 13.0.4 and `LiteNetLib` 2.1.4 runtime dependencies, plus Debug-only GdUnit4 test packages.
- Current renderer setting: `gl_compatibility`, using Godot's 2D `CanvasItem` stack. The intended art pipeline uses `Light2D`, `CanvasModulate`, `LightOccluder2D`, normal maps, and custom `CanvasItem` shaders.
- Target platforms: Windows and Linux/SteamOS, with Steam Deck performance in mind. macOS was cut from launch by the 2026-09-26 design decision G03.
- Simulation and presentation target: locked 60 FPS / 60 Hz physics.
- Reference resolution: 1920×1080. `project.godot` and `ViewportEnforcer` use fixed `keep` aspect behavior with black letterbox/pillarbox clear areas.
- Performance target: 16.67 ms per frame, no gameplay-time GC spikes, at most 4 GB runtime RAM, roughly 150 draw batches, 150,000 visible vertices, 60 active `AnimatedSprite2D` nodes, and 500 active particles. Pool short-lived gameplay objects.

### Dependency status

Klotho v0.6.1 and GdUnit4 v6.2.0 are pinned under `addons/`. Klotho is experimental; the fixed-point simulation and rollback foundation are implemented, and the Package 6 rollback-readiness gate (convergence, bounded history, worst-case depth-7 resimulation) passes across all nine kits and all ten stages in the .NET test host — but that is a single Windows Debug machine with an in-memory transport, so the platform and real-transport gates are still open. Steam Networking Sockets and Steam transport are not installed. Do not describe the existing networking path as production netcode.

## Scene architecture and flow

- Main scene: `res://scenes/menus/MainMenu.tscn`.
- **Temporary developer level select (2026-08-15, debug builds only).** The main menu's root screen carries a `LevelSelectButton` (`menu_level_select`, visible when `MainMenu.ShowDeveloperLevelSelect` — `OS.IsDebugBuild()` with an `internal static bool?` test override) that runs character → a **seventeen**-tile `LevelSelectScreen` (labelled `NN  <campaign_level_*>`, with Level 4A labelled `04A`) → difficulty, borrowing the authored character and difficulty screens under a `_developerLevelFlow` flag, and ends in `StoryManager.StartLevelDirect(level, characterID, difficulty)`. `PrepareDirectLevel` resets campaign state, sets `CurrentLevel`, marks the tutorial complete for anything past level 0, and clears `ActiveSaveSlot` to `-1` — no save slot is created or written, so a dev launch can never overwrite a real campaign (autosave inside the level no-ops). Retire the button, the screen, the two keys, and the gate together when it is no longer wanted; `MainMenuSceneTests` pins the flow, the hidden-in-release chain, and the slotless state.
- Scene changes use single-scene replacement through `GameManager.LoadScene`, `ResourceLoader.LoadThreadedRequest`, and `SceneTree.ChangeSceneToPacked`.
- `GameManager` builds a themed `LoadingScreen` per transition (Story portal / Fighter VS / plain variant, chosen from the destination path), parents it to the autoload so it survives `ChangeSceneToPacked`, runs it at `ProcessMode.Always` so a paused tree cannot freeze it, and enforces a two-second minimum display time.
- Cross-scene selections live in `GameManager.CurrentSession` (`SessionData`): selected character, selected stage, active save slot, difficulty, and `MatchSettings`.
- Default match settings are Stock mode, 3 stocks, 480 seconds, items on/**Medium**, and hazards on/**Medium** (V7.3 ruling #18, 2026-08-26; High remains a house-rule choice).
- **The campaign is a seventeen-slot explicit route, not a level index** (Package 11 A12). `StoryManager.CampaignRoute` is `[0, 1, 2, 3, 4, 16, 5 … 15]`; `AdvanceToNextLevel()` steps that list and `GetLevelScenePath` resolves **by ID, not array position**. `CampaignLevel.LegacyNexus = 16` is an identity, not a position — nothing between `Tutorial = 0` and `Alexandria = 15` was renumbered. **Level 4A's scene path depends on the locked character**: `GetLevelScenePath(LegacyNexus, heroID)` → `res://scenes/campaign/Level_04A_<hero>.tscn`, with `ResolveLegacyHeroID` falling back explicit arg → session character → active save → `""` (a refusal, never a guess). `StoryManager` still validates a route before loading rather than changing to a broken scene; `tests/integration/CampaignRouteTests.cs` asserts every slot resolves on disk, that the manifest's `StoryLevel` rows agree with `GetLevelScenePath`, and that a sequential advance walks the route and caps at 15.
- Levels 2–15 are built on `StoryLevelControllerBase` (`scripts/Environment/`): geometry builders, `RoomTransitionTrigger` + `StoryCameraConfiner` room graphs with resume-time camera re-confinement, three checkpoints per level with **authored roles** (see Checkpoint roles below), dust tally, boss wiring, extractor placement, a virtual post-boss/exit/completion tail, and pooled-object release on unload. **The Tutorial and Florence deliberately do not extend it** — they predate the convention and were not retrofitted, which is why their manifest rows are still `Prototype` while 2–15 are `Implemented`.
- **Level 4A (the Legacy Level)** is a shared `LegacyLevelControllerBase` (extends `StoryLevelControllerBase`) plus nine per-character variants, all at the campaign's functionally-complete/placeholder-presentation bar. `BuildLevel` is **sealed**: Entry checkpoint (self-activating, role `Entry`) → a movement gap → the Special 1 gate → the Special 2 gate → the independent `{levelID}_eraser_debut` trigger → the Nexus Resonance Source and its Ultimate set-piece → exactly one Restoration Font → the PreBoss checkpoint (role `PreBoss`, strike to activate, both roles enabled on **every** difficulty — there is no Middle) → a per-hero two-phase boss under `resources/Bosses/legacy/`. Every variant pays the same **15 required / 25 boss / 10 optional** dust row. A variant supplies eighteen abstracts plus its geometry and approach spawns and re-authors nothing else. `LegacyKitGate` modes are `Strike | Zone | Traversal | Nexus`.
- **The F04 Nexus Resonance Source** is a puzzle-only Ultimate authorization: armed by interacting in a cleared, hazard-free area, after which the normal Ultimate input casts the real Ultimate at the designated puzzle target **at any meter value including zero**, neither filling nor consuming the meter. Leaving the cast area, death, reload or an interrupted cast clears the arming; it re-arms on return with unlimited free retries; success latches the gate and disables the source. **It is never saved armed**, Time Freeze can neither arm nor cast it, and it never lights the F13 Defy seal.
- **Levels 13–15 are the Act III gauntlet and do not return to the hub** (Package 11 A3b). They chain level → level; the hub is unreachable until campaign completion, and Act III's completion auto-deposit is the gauntlet's banking event (since Package 12 W2 / H02, every level banks only in its completion transaction — see the Story progression section). Level 15 still ends the campaign: post-boss beat → Temporal Core insertion at the Prime Anchor → `CampaignCompletionSequence` (ending dialogue → credits → `SaveManager.MarkCampaignCompleted()` → MainMenu), with the completion flag written when the credits **begin** so quitting mid-roll cannot lose a campaign the save has already advanced past. The ending variant is chosen by **N05**: exactly fifteen level IDs (Levels 2–15 plus the hero's one 4A), compared **unrounded** against `CleanEndingThresholdPoints = 750f`, identical on every difficulty. When a save `IsCompleted`, the hub's Temporal Portal shows a "timeline restored" state instead of reloading level 15.
- **Calibration Drills (F18)** have two entry points (Package 11 A11). Standalone: a `CalibrationDrillsButton` on the main menu's root screen, between Fighter Mode and Settings, available on a first boot with **no Story save**, running `CalibrationDrillPicker` → `CalibrationDrillList` → `HolodeckDrill`. From the hub: the Holodeck console's second entry, which skips the picker (a campaign save locks its character) and returns to its own hub. Route state is `SessionData.CalibrationReturnScenePath` / `CalibrationDrillIndex`, **never persisted**, and `FTT.Combat.CalibrationRoute` owns the paths and both routing rules. Six scripted drills (block string, landing tech, launch DI, grab/throw, Echo Step, Rally reclaim) run on Florence's **Sealed** geometry with 60 s attempts and a 3-miss tolerance; the last drill hides "Next Drill".
- `TestArena` uses `FighterSimulationDriver`: Klotho state is authoritative and the two `PlayerController` nodes are collision-free presentation adapters. The local human/CPU match core, rules, results, rematch flow, and stage select are functional. **All ten catalog stages are authored production-contract scenes** (`scenes/fighter/FighterStage_*.tscn`, Package 6, 2026-08-08): each has its own `FighterStageGeometry` entry (fixed-point walls, ceiling, blast zone, spawn distance, two or three one-way platforms, **floor segments**, hazard and orb anchors), its own `FighterStageController` scene with era-distinct placeholder presentation and a `ParallaxBackground`, its own `FighterCamera` midpoint/zoom wiring, its own pool config, its own `StageAudioSet`, and its own preview plate. Each stage carries one of ten era-specific deterministic hazard identities with real warning/active/recovery phases (`CooldownFrames` is the recovery length), per-type movement/targeting/dwell/idle behaviour, one-shot per-fighter hit masks where specified, and the block-absorbs-a-tick rule at one shield charge. `FighterStageConformance` (shared validator) pins every scene's markers and colliders against its fixed-point geometry through `pixel = (950 + x*62.5, 700 - y*62.5)`, and every stage ships a per-stage GdUnit suite. Production art, music, and VFX remain Package 10.
- **Open and Sealed stages** (Package 11 A9). The main floor is authored as `FighterStageGeometry.FloorSegments`; **an empty array is the sentinel for an unbroken wall-to-wall floor**, which is what the seven Sealed stages and the legacy flat arena carry. **Three stages are Open** — Paris Bastille (a 5.0-wide centre courtyard pit, respawn anchor moved to (−4, 3) because stage centre is now a hole), Vesuvius Caldera (a 2.5-wide collapsed shelf against the right wall) and Nassau Flagship (a 3.0-wide stern gap). Their pits are genuinely reachable through ordinary play, which closes the 2026-08-08 audit's H-11. Pit-facing segment ends are true grabbable ledges, encoded on the existing `LedgeAnchor` int as `(Platforms.Length + segmentIndex) * 2 + side` — **no new snapshot field**, `FighterRuntimeComponent` is still exactly full at 128 bytes. Ground support, the ground snap and the drop-through gate are all per-x (`HasFloorSupport(x)`). Respawn anchors are per stage. The catalog carries `FighterStageData.IsOpenStage`, shown as a badge in stage select and the Holodeck and cross-checked against the geometry by a test.
- Campaign scenes attach shared services through `StorySceneBootstrapper` (`scripts/Environment/`): a resource-driven `DialogueManager`, reusable `StoryHUD`, pause menu, and (for levels) the rewind manager and presentation overlay. Dialogue content lives in `DialogueSetData`/`DialogueSequenceData` resources under `resources/Dialogue/`.
- The Tutorial, Florence (gear-puzzle room gating, triggered waves, boss, results, autosave), and hub (Calibration Bay anchor, Holodeck CPU practice loop that returns to the hub, Sarah NPC, Repository deposit ledger) flows are functionally complete with placeholder presentation. `StoryDifficultyTuning` scales Story enemy HP/damage at spawn without touching Fighter loadouts.
- **Level 0 was rebuilt for V7.6** (Package 11 A5/A6b). Part 1 opens on the four-beat ignition: the cold Unbound extraction beam **bites**, gold **ignites on the hero**, the beam **breaks**, and a clean concentric **Warden portal** opens beside the tear — the "two kinds of door" rule the whole game's visual grammar rests on. Calibration is now `BasicHits → RallyReclaim → Block → Grab → HitstunDI → LandingTech → MeterAndDefy → UseRewind → UseTimeFreeze → Done`; the Special, Ultimate and movement-ability lessons are **deleted**, because the Legacy Unlock Schedule means the player does not have those slots yet. Part 3 is authored for base jump reach (double jump → roll), with no movement-ability corridor. The Grab lesson uses a guard that restores its HP on every swing until the player grabs and throws; the Hitstun Agency lesson uses a scripted free launch (no HP, no Rally, no meter, no rewind charge) with a tutorial-only hitstop for the ±15° DI read and a mandatory landing tech; Meter & Defy fills the meter, lights the F13 seal and spends it on a scripted lethal-tagged hit.
- Level *geometry, actors and hazards* are still built programmatically in the level controllers — valid prototyping state, not the intended final asset pipeline. **UI is no longer in that bucket**: as of Package 8 every production screen (main menu with its four-screen stack, Fighter character/stage/rules select, settings, both pause menus, both HUDs, dialogue box, resonance grid, level and match results, both loading variants, credits) is an authored, themed, focus-authored `.tscn`. Where a widget's *count* is data-driven (stock pips, shield charges, cooldown slots, resonance node buttons, character tiles' colour identity) it is still built in code inside the authored scene, deliberately — authoring a fixed number would cap the HUD at today's defaults.

Use the existing static `Instance` pattern for these services. ## Gameplay architecture

### Character data and runtime controller

- Static identity and baseline tuning are Godot `Resource` objects (`CharacterData`) stored as `.tres` files.
- Story runtime behavior is owned by `PlayerController : CharacterBody2D`. Fighter runtime behavior in the Test Arena is owned by `FighterSimulation`; `PlayerController` is presentation-only there.
- The canonical state set is `Idle`, `Running`, `Dashing`, `Rolling`, `Skidding`, `Crouching`, `Airborne`, `Attacking`, `UsingSpecial`, `UsingUltimate`, `Blocking`, `Stunned`, `Dazed`, `LedgeHanging`, `Dead`, `Respawning`, `UsingMovementAbility`, `Grabbing`, and **`Thrown`** (F23, appended after `Grabbing` by Package 11 A1c). `Dashing` keeps its ordinal as a permanent reservation. A thrown victim rides out its own state: no landing tech, no block escape, fixed trajectory.
- Universal movement uses a fourteen-frame grounded run ramp, a twelve-frame grounded stop/decel ramp (gameplay-feel batch 2026-08-10; `RunAccelerationFrames`/`RunDecelerationFrames`), a stateless fast-fall (Down held while airborne **snaps** vertical speed to `FastFallSpeed` **20** units/s downward — equal to `UniversalMovementRules.TerminalFallSpeed` — and cancels Warp float, both modes, no snapshot state; Package 12 W3/M01, D1(a): the sim also clamps every fall at the 20 u/s terminal, while Story's ordinary terminal stays 600 px/s = 10 u/s until H-7), and a 4-startup/12-travel/10-recovery evasive roll; the first eight roll-travel frames are invulnerable and roll travel disables the combatant pushbox. These timings live in `UniversalMovementRules` and must remain aligned between Story and Fighter simulation. **The universal dash was removed on 2026-08-09 by explicit user decision, superseding `design-godot.md`'s 12-frame `1.35x` dash spec** — the roll and each character's movement ability are the mobility tools. `CharacterState.Dashing`, `UniversalMovementPhase.Dash`, and the protocol-v2 Dash button bit remain reserved (never reuse them); enemy `ChargeDash` archetypes and character abilities that dash by name are unrelated and stay.
- Movement also includes direction-reversal skid, coyote time, jump buffering, short-hop behavior, air control, crouching, one-way platform drop-through, ledge hanging, and recovery. **Every character has a double jump as of 2026-08-10** (`MaxJumpCount` is 2 across the roster; run speeds −15% and jump forces −20% height in the same batch — the nine `.tres` values are law). On 2026-08-15 the `MaxJumpForce` spread was compressed from 10.0–13.5 to **11.5–13.0** by user direction (heavies jumped too low; ordering preserved, Lincoln 11.5 → Pocahontas 13.0; `docs/GAMEPLAY_FEEL_2026-08-10_PLAN.md` §2.2 has the per-character map). The Fighter sim also ledge-grabs at authored platform ends (`FighterLedgeRules`, plan §2.11: capture falling or rising slowly into a 0.5-unit edge box, hang refills jumps, Jump climbs at 0.9× jump speed, Down releases with a 30-frame regrab lockout, 300-frame auto-release, hits knock the hang off); Story keeps its marker-based `LedgeGrabPoint` system, now also capturing while rising slowly. **Ledge V7.3 (2026-08-26), both modes:** the edge is contested, not shared — a second grabber trumps the hanger (an end-of-update resolution pass in `FighterMovementSystem` releases the earlier hanger — larger `LedgeStateFrames`, lower PlayerID keeps a same-frame tie — via the normal release path with the 30-frame regrab lockout; Story's `LedgeGrabPoint.TryAcquire` forces the occupant off the same way), and grabs are capped at `BasicComboRules.LedgeRegrabsPerAirtime` (3) per airtime via `FighterVerbComponent.LedgeGrabsThisAirtime` (Story mirrors on `PlayerController`), reset on grounding and stock loss.
- Story Mode may use native Godot `CharacterBody2D` physics. Local Test Arena Fighter Mode already uses Klotho fixed-point authority and must remain on that boundary; online work must not move authority back into `PhysicsServer2D`.

### Combat

- Hit detection is conceptually `Area2D` hitboxes against `Area2D` hurtboxes. Final activation timing should come from exact animation-frame callbacks, not broad body collisions.
- The basic combo has three hits using `0.8×`, `1.0×`, and `1.5×` `CharacterData.BasicAttackDamage` (the authored base damages were halved and Special1/Special2 `BaseDamage` doubled in the 2026-08-10 gameplay-feel batch; ultimates and movement abilities unchanged). Crouched and grounded-down attack inputs use the same three-hit string. **Two directional single strikes exist alongside the chain (2026-08-10):** Up held + attack is an upward launcher (grounded or airborne), and Down held + attack while airborne is a downward-hitting launcher (down-air); both use `BasicComboRules` frame data (7/8/18 and 6/10/16), 1.0× damage, 30-frame hitstun, mostly-vertical launch knockback, never chain, and reset the combo index. Selection is the shared pure helper `BasicComboRules.SelectAttackVariant`. The new `gameplay_up` action (W / stick-up / dpad-up) feeds the vertical axis; Jump no longer contributes to it, so Warp-style up reads follow the Up input.
- **Basic-combo timing and chain rules live in `FTT.Combat.BasicComboRules`** (2026-08-09 cross-mode parity pass, revised same day for attack-on-the-move): per-hit startup/active/recovery frames (grounded totals 27/30/45, aerial 25/28/40), the 30/40/24-frame hitstun table (hits one and two hold a non-blocking victim through the buffered chain's connect-to-connect gaps — a grounded victim holding Block escapes hitstun into the stance, but as of the 2026-08-26 V7.3 pass only from hit two on: hit 1's hitstun is never block-cancelable), the 1x/1.2x/**4.5x** `KnockbackMultipliers` (the finisher launches the victim beyond melee range — ≥2.5 units separation pinned across all nine kits), the 24-frame chain-hold/buffer window, the Story-enemy 24-frame stun floor for `combo_N` hits, and the block-regen interval. Story's `PlayerController` timelines and the Fighter sim's phase machine (`FighterBasicAttackRules` in `scripts/FighterSim/FighterSimulationSystems.cs`) both consume it — never author a second copy of these numbers. Unified behavior in both modes: **swings keep full input steering** (grounded run ramp and aerial drift alike) with facing following held movement mid-swing (2026-08-10, superseding the whole-string facing commit; hitbox placement still reads facing at active-start); **held movement never cancels or resets the chain** (movement-cancel let a moving attacker restart hit one faster than the authored pace); jump/roll/block cancel the recovery and chain-hold window and reset the chain; a special or the ultimate cancels a swing at any point; landing cancels an aerial string with no lag; being hit into hitstun cancels the string; whiffed swings chain only through the buffer/hold window; and knockback **replaces** velocity.
- Specials and ultimates use `AbilityData.BaseDamage`; multi-hit totals derive from per-hit damage and hit count.
- Knockback target: `baseKnockback / (1 + target.Weight)`, then scaled by the victim's missing HP after the hit — `×(1 + missingHPFraction)`, linear 1× at full HP to 2× at zero (`BasicComboRules.LowHealthKnockbackScale`; sim chokepoint `FighterDamageRules.ApplyFighterHit`, Story `DamageCalculator` overload; `BossController.ApplyKnockback` deliberately unscaled — recorded open inconsistency). There is no armor/defense stat that reduces HP damage.
- A special may cancel a basic attack when allowed by the FSM/cooldown rules. Block may cancel only during recovery frames.
- Blocking stops movement and is front-facing. Three basic hits exhaust the three shield charges; any special shatters the shield; ultimates bypass it. Guard break causes a one-second daze. Both modes enforce the grounded block stance (2026-08-09): no absorb while airborne, mid-swing, or mid-roll; attack and ability inputs are ignored while the stance is up; and one charge regenerates per `BasicComboRules.BlockChargeRegenFrames` (180) while not blocking, in the sim as well as Story. **The V7.3 block-model closure landed 2026-08-26** (closing audit H-5; both modes): a non-shatter blocked hit locks the blocker into the stance for `ShieldstunFrames` (8 — no drop, grab, roll, jump, or drop-through, and grabs *whiff* against a shieldstunned target); a shatter freezes both parties for `ShatterFreezeFrames` (16, replacing the blocked 2f hitstop) and arms `BlockShatterLockoutFrames` (300) during which the stance cannot rise and regen is held (charge #1 at shatter+480f; stock loss clears it — **a charge restore never ends the lockout**, V7.6 F17 deletes that rule, and `RestoreAllCharges()` no longer zeroes the lockout timer); an empty shield never raises the stance; the 2026-08-10 hitstun block-cancel is gated to hits two and three of the string (hit 1 arms `HitstunBlockCancelBlocked`); a grabbing or held fighter has no functioning shield (attack beats grab); and landing tech reads the raw Block input, unaffected by charges or the lockout. The 2.0 s design regen figure stays retired (3.0 s, settled 2026-08-22).
- **The V7.6 defensive contract D01–D04 landed 2026-09-13 (Package 11 A1b, both modes).** Per distinct eligible hit contact the resolution order is **hit eligibility / invulnerability → the D04 Defy window → projectile immunity → Temporal Aegis → HP barrier → ordinary block → HP**, stopping at the first layer that fully prevents the hit. **Full absorption spends no block charge and applies no stun, knockback, status or combo mark** — including at exact depletion; partial absorption passes only the remainder, at the attack's original `AttackClass` / `BlockChargeCost`. Story routes the hurtbox path, DoT ticks and hazard ticks through the one shared `PlayerController.ResolveProtectionLayers`; the sim does the same above `ApplyFighterHit`'s block branch. **D04:** a Defy proc releases the survivor from the triggering hit's hitstun, launch, tumble, stashed DI and capture, zeroes that hit's knockback/hitstun/status, and grants **60 active ticks** of protection counted from the first resumed normal-control tick (ticks 1–60 protected, tick 61 not), paused under hitstop / Time Freeze / suspended presentations. It is not immunity to a non-hit death — `KillPlayerNonHit` is untouched. **D02a** grants are identity-keyed: a repeat grant of the same effect refills to cap and restarts the timer, never adds, and a repeated `grantEventId` is refused outright; granted shields live `GrantedShieldLifetimeFrames` (480). **D02d** Wardenclyffe recharges at 2.5 % of MaxHP per live second (empty→full is exactly 6 s at any MaxHP), arms a 3-second damage delay on capacity *or* HP loss, and absorbs **only inside an owned coil radius**. **D02e** Story gained Temporal Aegis (`OrbEffect.TemporalAegis`) as an active flag, never a charge count. **D03d** a throw bypasses finite shields (`HitPayload.BypassesFiniteShields`). **F15** Divine Piercing and The Emancipator are ordinary Special-class **full** shatters in both modes — the two-charge shield-stutter behaviour is gone.
- **Rally and meter origin (D03f–D03h).** Rally reclaim heals `min(pool, credited × 2.0, missingHP)` and debits only the HP actually healed, so a full-health attacker no longer burns its pool for nothing. **Zone ticks never reclaim** (`collectsEcho: false` at the sim zone pulse, all three expiry launches and `PlaceholderZone.CreditOwner`). **Ultimate-origin damage earns the caster zero damage-dealt meter** — `AddInfluenceFromDamageDealt(dealt, collectsEcho, ultimateOrigin)`, routed from all nine ultimate scripts, `Hitbox` and `PlaceholderZone` (via the **authored** `HitPayload.Origin` / `AbilityData.Origin` since Package 12 W3 — no longer the attack class or the slot), the sim zone pulse, `ApplyIntent`'s ultimate branch and the Cataclysm coil chain.
- **Echo Step is exact (V7.6, Package 11 A1c).** The retired ring held 5 samples written every 6 frames and read the oldest, so the destination was 24–30 frames back depending on phase. It is now **31 consecutive per-tick position samples and the exact `t − 30` one** — with 31 slots the write head *is* the `t − 30` slot, so there is no search, rounding or interpolation. Sampling is hoisted above the hitstop short-circuit, so an advancing hitstop tick records the same position. Generations open at spawn, at a stock loss and at Sudden Death setup, and spawn-filled storage is never counted as history: a fighter must genuinely live 30 further ticks. **Exact-or-no-teleport:** the destination is validated *before* anything is spent (an invalid or unavailable one refuses at no meter and no cooldown cost and does not start the wind-up) and rechecked at wind-up completion (a destination that became blocked **cancels with the committed cost retained** — no refund, no nearby substitute, no added immunity). Story mirrors all of it on `PlayerController`.
- **Same-frame chord priority** is the single shared table `BasicComboRules.SelectRecoveryVerb`: **the chord beats the single input, and the priced verb beats the free one.** A chord whose priced verb is unavailable falls back to the block-cancel rather than eating the input. Before this the ordering was incidental — the sim happened to call `TryStartEchoStep` eight lines before the roll cancel and Story called all three verbs from three separate sites.
- **Fighter modes are Stock or Time only (F21).** `MatchMode.Hybrid = 2` is `[Obsolete]`, reserved and **removed from both selectors**; a legacy saved `Mode == 2` normalizes to timed Stock with a valid positive timer. **Time is decided by fewest stocks lost**, with unlimited respawns and **no HP tiebreak** — `FighterMatchComponent` now counts victim-side `PlayerOneStocksLost` / `PlayerTwoStocksLost` fed from the single `ApplyStockLoss` chokepoint (it used to count the KOs a player *scored* and pick the larger, the opposite bookkeeping). Equal totals, 0-0 included, enter Sudden Death.
- **Sudden Death (F22)** is a shared round reset. Retired: the **1-HP clamp**, the **forced-hazards-on** override, and the **pre-marked Defy flag**. Living fighters keep their exact current positive HP (unequal included); a fighter dead or respawning at the end of regulation gets its normal respawn HP once, recorded on component 319 so a duplicate transition cannot grant it twice. Hazards respect the house toggle — **Off stays Off**; On runs twice-normal cadence with a full first warning. Meter 0, every cooldown ready, block refilled, both status slots / Rally pool / marks cleared, regulation projectiles/zones/constructs/hazards swept, orbs disabled, invulnerability cleared. Defy is disabled by **derivation** from `SuddenDeathActive`, so the spent flag is preserved and entry consumes no use. Regulation stocks-lost totals are frozen on component 319 and reach `MatchResults`.
- The Influence/Ultimate meter ranges from 0 to 100. Damage dealt adds 1 point per HP; damage taken adds 0.25 per HP. Using the ultimate resets it. Fighter stock loss retains 75% of the current meter.
- **The V7.3 combat batch's second half landed 2026-08-26** (PRs 4–7, both modes where applicable): Rally reclaim is now `min(pool, hitDamage × BasicComboRules.RallyReclaimDamageMultiplier (2.0))` — the pool persists and keeps draining at the unchanged rate (no more one-poke full-pool cashouts; a defied hit still generates no echo, and throws collect the echo like any direct hit); Story environmental damage routes through the new `PlayerController.ApplyEnvironmentalDamage` chokepoint (extractor discharge, drown/searchlight/rift ticks, escape catches, Level 1/7 hazards, `StageHazard` — Defy-flag consumption, echo accrual, victim meter; `StageHazard` also gained a per-body float damage accumulator, fixing the `(int)(Damage*dt)` truncation that dealt zero at 60 FPS); the Story landing tech is a real 12-frame locked window (invulnerable, in place, no actions, then Idle — and the old `IsOnFloor() && !_wasGrounded` landing test was unsatisfiable, so Story tech had never fired at all; a per-stun airborne latch fixed it); Sudden Death disables Chronal Orbs (live orbs cleared on entry, `FighterOrbSystem` early-returns; **the "hazards stay forced on" half was superseded by V7.6 F22 — the house toggle is respected**); timeout compares HP as a percentage of max with echo pools excluded (**superseded by F21: Time is now decided by fewest stocks lost, with no HP tiebreak**), a simultaneous final-stock KO enters Sudden Death, and a dual lethal trade at 100/100 meter fires both Defy procs (sequential intent application; the second attacker legitimately re-earns meter from its own post-shatter hit); the Paris Dampening Beam drains 2.5 meter points per 30-frame tick (the doc's 5%/s — the old 5/tick was double); and mirror matches are allowed (the character-select duplicate-pick refusal and its unavailable-feedback plumbing were removed; a doubly-locked tile blends both lock colours).
- **V7.4 Enemy Stagger Discipline landed 2026-08-29 (Story-only; ends the PvE stun-lock).** Constants live in the new rulebook `FTT.Combat.EnemyStaggerRules` (`scripts/Combat/EnemyStaggerRules.cs` — plain constants, no Godot types); the behavior lives entirely in `EnemyController`. Four rules: **armored getup recovery** — a NATURALLY expiring hitstun arms `GetupArmorFrames` (36, 0.6 s) during which hits deal full damage but apply no stun and no knockback, the enemy acts freely, and the shared gold hyper-armor glow plays (a hit landing mid-stun still refreshes stun normally — the string and finisher are untouched); an **elite stagger budget** (`Tier == Elite`, which includes the Chrono-Warden) — each post-resistance applied stun accrues, decaying 1 s/s while unstunned, and exceeding 2.0 s triggers **Armored Recovery** (1.5 s flinch- and knockback-proof, budget reset, and an immediately committed signature attack through the normal `BeginAttack`/`SelectNextAttack` path — elite ability if off cooldown, else primary — so the ordinary class colour + glyph telegraph plays); **diminishing special stun** — a Special-class stun landing within 4.0 s of the previous special-sourced stun on that enemy applies full damage but stun ×0.5, window refreshed per special (basics and ultimates untouched); and the **pressure-exit rule** — stun or armored recovery ending with the target inside `AttackRangePixels` prefers `EnterAttacking` (normal reaction delay/cadence/cooldowns) over dropping to Chase. **Bosses are compliant with zero boss code**: `BossController` has no Stunned state and its hit intake ignores `HitPayload.HitstunDuration` entirely (pinned in `BossControllerTests`); `BossStaggerBudgetSeconds`/`BossArmoredRecoverySeconds` are authored for the day a flinching boss appears. **Scope guard:** nothing in `scripts/FighterSim` consumes `EnemyStaggerRules` — Fighter PvP keeps DI/tech/hit-2 escape as its whole answer (the amended No Juggling pillar).
- **V7.4 CPU hitstun defense landed 2026-08-29 (Fighter Mode, input-side only — no combat-rules change).** `FighterCpuController` no longer zeroes every input during hitstun: `CpuBandTuning` gains `HitstunDefensePercent`/`DiPercent` (Easy 10/0, Normal 45/40, Hard 85/80 per the design §10 Hitstun Defense rows), rolled **once per hitstun instance** (detected as `HitstunFrames` rising from zero or above the previous frame's value — a mid-stun refresh re-rolls). A successful defense roll holds Block — **exclusively**, so a scheduled attack edge can never read as the grab chord and drop the shield — through the hitstun, the tumble, ground contact, and a 45-frame grounded linger (`EscapeStanceLingerFrames`), buying the hit-2 escape, the blocked rest of the string, and the landing tech through the ordinary sim rules; a successful DI roll holds the stick toward safety during the launch window. The rolls ride the same recorded-input path as the existing BlockPercent draws, so rollback replays them; the daze branch still returns None. The full constructor gained an optional `CpuBandTuning? tuningOverride` test seam. `FighterCpuHitstunDefenseTests` pins the matrix, the roll gates, and both sim integrations.
- **V7.4's "pit-aware DI is deliberately not implemented" sentence is retired.** Package 11 A9b ships it: `ResolveDiHold` aims at the **nearest pit-facing floor edge** while the launch trajectory ends over a gap, and keeps the unchanged toward-centre hold everywhere else. On Paris that is the difference between DI and suicide, because stage centre is the hole.
- **V7.6 F19 CPU recovery and verb policy landed 2026-09-13 (Package 11 A9b, Fighter Mode, input-side only).** The inverted percentage ladder is replaced by a tiered planner: **Easy** steers at the nearest legal landing, spends its jumps, and gets **one** movement-ability activation per offstage episode with **no Specials anywhere**; **Medium** estimates reachability with the jumps in hand and otherwise spends one suitable ability, the movement ability by default, also capped at one per episode; **Hard** compares routes, chains where the kit actually refunds, and past `OffstageStallLimitFrames` (240) drops every optional hesitation so it cannot stall offstage. The **offstage episode latch** is input-side and outside the rollback snapshot, and ends only on a stable landing on *authored* stage geometry, a legal ledge capture, or a KO — so a jump refund or a temporary staff platform does not reset the cap. The activation is charged **at delivery, not at decision**, because the 128-slot schedule ring can overwrite a pending slot under Easy's jitter. Recovery detection is "unsupported over a gap", reachable only on Open stages (`HasFloorSegments == 0` on a Sealed stage), so closed stages cannot trigger a false recovery — no Y threshold anywhere. `CpuRecoveryProfile` holds the nine per-character plans and is **built from the CPU's own normalized `FighterLoadout`**; it is code-owned like `CpuBandTuning` and **must never become a resource**, because Fighter Mode stays competitively normalized. `RecoverySpecialTwoPercent` is retired in favour of `RecoveryMobilitySpecialPercent`, which is **inert on every band** — no character approves a mobility Special (`VERIFY-CPU-MOBILITY-SPECIALS`). The CPU also uses **grabs and Echo Step**, emitted as the shared chords a human presses: Easy neither, Medium 25 % admission for both, Hard scored (a grab must actually improve position; Echo Step weighs the 30-meter spend against a viable Ultimate setup and an unused eligible Defy). Admission is rolled **once per opportunity** and a failed roll never reopens a continuing one.
- **M05/M07 launches and knockdown landed 2026-09-27 (Package 12 W3b, both modes).** Only a hit authored `Launches = true` launches — the basic finisher, Up-Attack, Down-Air, the three throws, and the abilities `AbilityData.Launches` marks (W3's proposal, still `VERIFY-ABILITY-LAUNCHES`). Only a launch grants DI, tumble and the landing tech. The string's row is `BasicComboRules.StringHitLaunchesFor(profile, step)` and **Lincoln's hit 2 launches** (`BasicStringProfile.Hit2Launches`, M07), so his victims get DI and tech instead of the grounded escape. **A missed tech is a knockdown**, a sub-phase of `Stunned`: `BasicComboRules.KnockdownFrames` (30) fully invulnerable and action-locked frames after the landing, then a get-up chosen from the held direction on the knockdown's last frame — neutral `NeutralGetUpFrames` (10, in place) or roll `RollGetUpFrames` (14 of travel at the roll's speed), neither invulnerable, both action-locked; a hit during the get-up ends it. The CPU's DI hold now fires only while airborne in hitstun (the input-side read of "launched"). Handoff: `docs/handoffs/P12_W3b.md`.
- Fighter Mode is HP plus stock, not ring-out-only combat. A timer draw compares stocks, then HP percentage; a true tie is logged as a match but not a win or loss.

### Ability implementation

- Shared ability metadata belongs in `[GlobalClass] AbilityData : Resource`.
- Executable abilities derive from `BaseSpecial` and follow startup → active → recovery → cleanup phases.
- Character-specific classes live in `scripts/Characters/Abilities/` and use the `FTT.Characters.Abilities` namespace.
- Persistent constructs such as Tesla coils, Leonardo's turret, vine snares, serpent nests, projectiles, VFX, enemies, pickups, and damage numbers should use `PoolManager`/`IPoolable` rather than repeated instantiate/free churn during gameplay.
- Persistent objects must have stable owner/type/state data so Story rewind and Fighter rollback can snapshot them.

### Status effects

**Two slots, and stronger-wins inside a slot** (Package 11 A1 — this supersedes the retired "one active status at a time / newest completely replaces the previous" rule). `FTT.Combat.StatusSlots` is the one data contract: a `Damage` slot and a `Control` slot, routed by the single compile-time table `FTT.Combat.StatusRouting.SlotOf`. Damage: `Venom`, `RadiantBurn`. Control: `TimeDilation`, `StaticCharge`, `Root`, `Suppression`.

Within a slot: a **different type always replaces**; the **same type replaces only when `newIntensity × newDuration >= currentIntensity × currentRemaining`**, bringing its own duration; a weaker same-type application is a **complete no-op** (no replace, no refresh — the occupant keeps its own remaining time). **The other slot is never touched.** Effects still do not stack, and there is no general cleanse or post-effect immunity. All four application sites share the rule: `StatusController.ApplyStatus`, `EnemyController.ApplyStatusEffect`, `BossController.ApplyStatusEffect`, `FighterDamageRules.ApplyStatus` (the last through `ShouldReplaceRaw`, an exact `int64` product of the FP64 raw intensity and the integer frame count — no division, no float, bit-reproducible across a rollback). `StatusController.IsDamageStatus` is retained as a forwarder to `StatusRouting.SlotOf`; there is only ever one routing table.

The canonical names are `TimeDilation`, `Venom`, `StaticCharge`, `RadiantBurn`, `Root`, and **`Suppression` (= 6, appended)**. Suppression is **Story-only**: 2.0 s standard duration, Control slot, and it refuses Special 1, Special 2, the Ultimate and the Movement Ability at the four cast sites **consuming neither cooldown nor meter** (cooldowns keep ticking). Basics, block, grab, Rally, DI, landing tech, Defy History, death rewinds and **Time Freeze** are untouched by it. `FighterDamageRules.ApplyStatus` **refuses `Suppression` outright**, so an authored `.tres` carrying it cannot enter deterministic state, and `EnemyController`/`BossController` refuse it too — it is a player verb. Presentation is `GlowPresentationController.SetAuraSmothered`, a separate channel that desaturates toward `GlowPalette.SuppressionColor` and restores the arbitrated layer intact when it lifts.

`FTT.Combat.IStatusEffectTarget` (`ActiveStatuses`, `ApplyStatusEffect`, `ClearStatusEffect(slot)`, `ClearAllStatusEffects()`, `TargetNode`) is implemented by `PlayerController`, `EnemyController` and `BossController`, and all three clear on death. It deliberately does **not** inherit a damage interface. **Package 12 W3 (M08) added `FTT.Combat.IDamageable`** (`float TakeDamage(in HitPayload)`, `bool IsAlive` — it returns the HP dealt, a deliberate deviation from the GDD's `void`), implemented by the same three controllers and by `Hurtbox` (so every `EnvironmentHurtboxAdapter` strike surface too); the two interfaces coexist. The M08 hit contract — `AbilityData.HitstunFrames` / `BlockClass` / `Launches` / `Delivery` / `Origin`, `HitPayload.SourceActorId` / `ContactId` / `Launches` / `Delivery` / `Origin`, and the pure `HitClassification` mappings — is recorded in `docs/handoffs/P12_W3.md`.

Update both snapshot paths and tests when changing status semantics.

## Fighter networking and determinism

`scripts/FighterSim/` implements a Klotho fixed-point (`FP64`/`FPVector2`) 1v1 foundation with quantized inputs, stable state IDs, full snapshots, deterministic hashes, a 120-tick history, prediction, corrected-input rollback, and resimulation. `FighterLoadoutFactory` accepts normalized base resources only, preserving Story/Fighter isolation. The Test Arena renders synchronized results without feeding Godot state back into gameplay.

The deterministic systems cover accelerated ground/air movement, universal roll phases (dash removed 2026-08-09), fixed-point fighter jostling, jump counts, solid side/top bounds, bottom-zone stocks, generic basics/specials/ultimates, block, meter, status, Stock/Time resolution (Hybrid is retired), projectiles, movement abilities (including input-directional Warp teleports with a reduced-gravity float window), deploy-limited persistent constructs, Area-execution zones (`FighterZoneComponent`/`FighterZoneSystem`: impulse-free periodic damage/status pulses that bypass shields and never zero velocity, plus owner-overlap speed bonuses like Einstein's Relativity Rift), stage hazards, and Chronal Orbs. `FighterStageGeometry` supplies per-stage fixed-point bounds, one-way platforms (with drop-through and edge-walk-off rules), spawn distance, and authored hazard/orb anchors; stages without authored geometry fall back to the legacy flat arena. Seven stages have an unbroken base floor (empty `FloorSegments`); three are Open. Character-specific production behavior and rollback performance/platform gates remain incomplete. Klotho v0.6.1 is experimental and this is not production online netcode.

## Coding and content conventions

- Match folder namespaces: `FTT.Core`, `FTT.Characters`, `FTT.Characters.Abilities`, `FTT.Combat`, `FTT.Enemies`, `FTT.Environment`, `FTT.UI`, `FTT.Networking`, and `FTT.FighterSim`.
- Godot C# node/resource classes are `partial`; reusable inspector data classes should use `[GlobalClass]` and `[Export]` fields/groups.
- Use `res://` paths for Godot resources. Prefer exported `PackedScene`, `Resource`, and typed node references over scattered magic paths.
- Keep static tuning in Resources and runtime mutable state in controllers/snapshots. Avoid creating a second canonical value in a factory or UI script. Ability-scoped Resonance lanes are read through `PlayerController.StoryScoped(key, abilityScope)`; the scoped bucket is copied in **one** assignment by `CharacterFactory` — never as a second per-ability field.
- **Save payload classes are plain data with no engine dependency, and must stay that way.** Never read a resource, a manifest or any `res://` path from a `GlobalSaveData` / `StorySaveData` field initializer or from `Normalize()`. Pure-C# GdUnit suites construct and normalize those objects with no Godot runtime, where a `FileAccess` call is an **uncatchable** access violation that kills the whole test host (CLAUDE.md failure signature A6b). Engine-side defaults belong on the autoload — `SaveManager.EnsureRosterUnlocked` is the pattern. The same caution applies to `CharacterRoster`, `CampaignCaptiveRoster` and `ContentManifest.LoadDefault()`: they need the engine, so only autoloads and `[RequireGodotRuntime]` suites may reach them.
- **A retirement source gate makes the retired noun unusable in identifiers anywhere in the repo, test names included.** `TimeFreezeTests.TheRetiredTimeVerbLeavesNoTraceInTheSource` scans every `.cs` under `scripts/` and `tests/` for the assembled manual-rewind token after stripping comments — so a pin that has to *name* the thing it retires must name it in prose, not in a method name.
- **Any GdUnit case that adds a grouped node to the `SceneTree` root must free it in a `finally`.** A leaked `StoryPlayer` is a session-wide failure amplifier: every Story suite that resolves the player by group then picks up a foreign dead fighter, and the resulting cascade points at seams that do not exist.
- **A test that walks a fighter across an authored stage has to respect `FighterStageGeometry.FloorSegments`.** `IsOpenStage` is the cheap guard; a chase loop that ignores it ends in a ledge hang, a 300-frame auto-release and a lost stock instead of the setup it meant to build.
- Poll named InputMap actions through `InputManager.Actions`. Preserve device/player separation for local 1v1; direct global input polling can make both fighters react to one device.
- Gameplay state changes belong in `_PhysicsProcess()` at 60 Hz. `_Process()` is appropriate for presentation/loading/UI, not authoritative combat simulation.
- Use `EventBus` for cross-system events, but keep payloads sufficient for consumers and avoid hidden global coupling.
- Pool frequently spawned or destroyed gameplay objects. Reset every mutable field in `OnSpawn()`/`OnDespawn()`.
- Dispose engine-returned Godot collection wrappers (`GetNodesInGroup`, `GetChildren`, `GetOverlappingBodies`/`Areas`) deterministically at recurring gameplay call sites: bind the result, then `using var lifetime = result.AsDisposable();` (`FTT.Core.GodotCollectionExtensions`). Wrappers left to the GC land on the finalizer queue, and a collection finalizer that runs during engine teardown crashes the process (`0xC0000005` in `godotsharp_array_destroy`); `GameManager._ExitTree` drains the queue at quit as the backstop, but deterministic disposal is the first line of defense and also avoids gameplay-time GC pressure.
- **Never call `Dispose()` on a Godot `Resource`** (or any `RefCounted`), in production or test code. Reference counting owns their lifetime. Disposing one that another Godot object still references — or that a parent resource will release — double-disposes its C# script instance and trips `CRASH_COND(gchandle.is_released())` in `mono_object_disposed_baseref`, which kills the process with `0xC000001D` at some unrelated later point. `Free()` the *node* and leave its resources alone.
- **Load authored `.tres` data resources through `FTT.Core.AuthoredResources.Load<T>()`, not `ResourceLoader.Load`/`GD.Load`.** `CharacterData`, `AbilityData`, `EnemyData`, `BossData`, `EnemyAbilityData`, `ResonanceGridData`, `DialogueSetData`, `ScenePoolConfig`, `StoryDropTable` and friends are immutable tuning data; the cache pins each one for the process lifetime. Loading one, reading it, and dropping the reference destroys the whole scripted graph — including every sub-resource behind an `Array[ExtResource(script)]` export — and rebuilds it on the next call, and that churn races the .NET finalizer thread into the same crash. Scenes, textures, audio, and anything pooled or streamed must *not* go through the cache; they are meant to be released.
- **Physics in/out signal callbacks cannot mutate physics-space state.** While an `AreaEntered`/`BodyEntered` handler (and everything it cascades into — hit resolution, kills, drop spawns, lethal-hit rewinds) is running, the engine rejects reparenting collision objects, toggling `Area2D.Monitoring`/`Monitorable`, disabling collision shapes, and `ProcessMode` writes on collision-bearing subtrees ("Function blocked during in/out signal" / "Can't change this state while flushing queries" / "Disabling a CollisionObject node during a physics callback"; a body added mid-flush is left with a null space and later crashes `MoveAndCollide`). The engine exposes no query for this state, so the codebase marks it itself: signal entry points that can cascade wrap their body in `using var scope = FTT.Core.PhysicsCallbackGuard.Enter();` (see `Hitbox.OnAreaEntered`), `PoolManager.Release` defers itself while the guard is active, monitoring/shape/process-mode writes go through the `PhysicsSafeSetters` extensions (`SetMonitoringSafe`/`SetMonitorableSafe`/`SetShapeDisabledSafe`/`SetProcessModeSafe`), and trigger callbacks that spawn collision bodies (wave triggers, `RoomTransitionTrigger`) hop off the flush with `Callable.From(...).CallDeferred()`. Direct calls — which is how tests drive these paths — stay fully synchronous; never "fix" one of these sites with an unconditional `CallDeferred` that would break that.
- **Whoever sets `SceneTree.Paused` hands it back, including on teardown.** Release it in `_ExitTree` as well as on the normal path (`DialogueManager`, `PauseMenu`), and restore it in a test's `finally`. A leaked pause freezes the next scene in game, and under GdUnit4 it stops the runner's transport node and hangs the whole test session.
- Keep Story-only progression modifiers out of shared Fighter stats and ability resources. **Nothing in `scripts/FighterSim/` may consume Story progression** — no Resonance grid values, no `StoryAbilityPerks`, no `StoryDifficultyTuning`, no `EnemyStaggerRules`, no `TimeFreezeController`, no `Suppression`, no `LegacyUnlockSchedule`. `CharacterFactory.CreateCharacter(..., applyStoryProgression: false)` remains the isolation seam, and A7b added a **separate** `applyLegacyUnlockLocks` parameter so F20's Hard-only perk mirroring can coexist with "core-kit access independent of Story ability locks" — do not collapse the two back into one switch. Conversely the Legacy Unlock Schedule, Suppression's ability lock and the Nexus Ultimate authorization are **Story-only gates**: Fighter Mode, CPU matches, the hub Holodeck and the Calibration Drills always run full normalized kits.
- **Level 4A is the only level allowed to require a specific character's abilities (V01c).** A `LegacyKitGate` grants that ability no general puzzle eligibility anywhere else, may require only a **canonical kit slot** and never a purchased Resonance node, and a Traversal gate's landing box must sit where the hero is **during** the movement-ability cast rather than at the far landing, because `LegacyKitGate.TraversalGraceFrames` is only 30.
- Preserve historical framing and the selected character's ability identity when adding mechanics; mechanics should not become generic solely for implementation convenience.
- Update translation keys, save schemas/migrations, rollback snapshots, pools, and tests whenever a changed data field affects them.
- Preserve unrelated user changes in this working tree. Do not clean, reset, or rewrite generated/user-modified files outside the task.
