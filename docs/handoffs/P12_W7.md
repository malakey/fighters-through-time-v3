### M35 — hero-name tokens and the name table
- `FTT.Core.DialogueTokens` is pure C# and resolves four tokens: `{HeroName}`, `{HeroAddressName}`, `{HeroPossessiveName}` and `{HomeEraName}`.
  - The tokens are resolved from the `hero_name_* / hero_address_* / hero_possessive_* / hero_home_era_*` rows, keyed by the **saved** hero ID.
  - A missing hero falls back to the `*_fallback` rows, then to a fixed English word. A raw key never reaches the screen.
- The tokens are resolved inside `DialogueManager.SubstituteCaptiveNames`, which is kept as the one render-time token pass, so the call site did not change.
- The nine-hero table plus the fallback rows are 40 keys. They are registered on `UnusedTranslationKeyTests.DynamicKeyPrefixes`.
- 26 lines that used "Traveler" were rewritten: the vocative became `{HeroAddressName}`, the boss taunt and the ending narration became `{HeroName}`, and Okafor's generic noun was reworded.
  - "Traveler" now survives only in `dlg_l00_intro_1`, Sarah's nickname. `DialogueTokenTests` pins this.
  - `dlg_l00_intro_2` is `{HomeEraName}?` and `dlg_l15_ending_4` is "Thank you, {HeroAddressName}.", both per the master.
- The pseudo-locale gets `FTT.UI.PseudoLocale`: +40 %, accented, bracketed, with placeholders untouched. `PseudoLocaleExpansionTests` covers every `en.csv` row.
- D6(a) is recorded as `DEFER-VARIANT-KEY-SEPARATOR` in the ledger.

### GAP-15 — act-boundary hub dialogue
`FTT.Environment.HubDialogueSelector` is pure C#. It maps the next mission and the completion flag to a period, and each period to a Sarah set and an Okafor set:

| Period | Next mission | Sarah | Okafor |
|---|---|---|---|
| Prologue | Tutorial, Florence | `hub.sarah_briefing` | none |
| ActI | L2–L5, 4A | `hub.sarah_act1` | `hub.okafor_act1` |
| ActII | L6–L12 | `hub.sarah_act2` | `hub.okafor_act2` |
| ActIIIDeparture | L13–L15 | `hub.sarah_act3` (**retargeted** as the final departure before the lockout) | `hub.okafor_act3` |
| Epilogue | campaign completed | `hub.sarah_epilogue` (new) | `hub.okafor_epilogue` (new) |

- **Once-only playback:** the period's Sarah set auto-plays on the first hub arrival of that period.
  - "Seen" is read from the slot's `ViewedDialogueIDs` effect ledger, which both the completion path and the skip path write.
  - The hub writes the slot when a `hub.*` sequence completes.
  - A slotless hub never auto-plays, so it never takes the pause.
- Talking to Sarah or Okafor replays the current period's set.
- Medic Okafor got an Observation Deck post (`MedicOkafor`, x=560).
- `hub.sarah_act3` stays inside the knowledge boundary: "fortress" is Level 12 knowledge, and the new hub lines contain no forbidden nouns.
