# P11 A10 — Chronal Dust economy (F05)

Branch `p11/A10`. Merged `main` at `1323c08` before validation.

Per-source dust is now an **authored inventory**, not a rate card. The contract fixes a *pool* per
level and says nothing about what any single enemy pays, so the shipped model — every enemy carrying
its own `ChronalDustDrop`, every Extractor a flat 15 — could not hit a budget row, and a level's take
moved with how many things the player happened to kill.

## What shipped

| Piece | File |
|---|---|
| Manifest schema (`[GlobalClass] LevelRewardManifest : Resource`) | `scripts/Environment/LevelRewardManifest.cs` |
| Pure allocator: floor + largest remainder, ties by stable source ID, fixed shares, even split, tier bonus | `scripts/Environment/RewardAllocator.cs` |
| Manifest → per-difficulty ledger; issuing, claiming, persistence, loss tally | `scripts/Environment/LevelRewardDirectory.cs` |
| 25 authored manifests | `resources/Content/reward_manifests/` |
| 15 boss resources 50 → 25 (+ the `BossData` default) | `resources/Bosses/*.tres`, `scripts/Enemies/BossData.cs` |
| Contract + implementation map + known gaps | `docs/DUST_ECONOMY.md` |

**Rules that changed behaviour:**

- **An unauthored source pays nothing** — it never falls back to a flat value. This retires "every
  enemy guarantees dust": a boss summon, an endlessly repeatable reinforcement, or a restored enemy
  whose source is already issued draws zero and spawns no pickup.
- **A difficulty changes the distribution, never the total.** Easy compiles a prefix of each wave
  exactly as the controllers spawn it, and the same pool spreads over fewer sources.
- `EnemyData.ChronalDustDrop` and `ChronalExtractor.DustReward` are **demoted in place to advisory
  fallbacks** for contexts with no compiled ledger (Test Arena, unit harness), not deleted.
- **Only the boss still forces a Large milestone plate.** An ordinary Extractor now shows the icon
  its actual award earns (Small 1-5, Medium 6-24).
- The results screen itemises **six** values: required enemies, boss, Extractors, secret/other
  optional, losses, Integrity tier bonus. `DustAwardSource.Secret = 3` is append-only.

## Level 4A is the one per-hero manifest

The nine Legacy Levels share `CampaignLevel.LegacyNexus = 16` and all carry the same locked row, but
each authors its **own** approach inventory — Cleopatra fields `plasma_spear_ward`, Shakespeare
`holo_page`, Tesla `voltaic_shock_drone`, and the six standards sit in different orders. One shared
source list would allocate against enemies the level never spawns.

- `LevelRewardManifest.FileNameFor(index, hero)` resolves `level_04a_<hero>_rewards.tres` **for index
  16 only**; every other level is unchanged.
- The locked character joins `LevelRewardDirectory`'s cache key for index 16 only, read from
  `GameManager.CurrentSession.SelectedCharacterID`.
- `RewardManifestTests` expands the 4A row per roster hero read from `content_manifest.csv` (never a
  literal list, matching `Level04AVariantCoverageTests`) and checks each manifest against its own
  controller's `ApproachSpawns` table — a variant whose layout changes fails naming the hero.

## Persistence

`StorySaveData.ClaimedRewardSourceIDs` joins A3b's additive per-attempt group (field initializer plus
a `Normalize` null guard), so `SaveVersion` stays **5** with no migration step, written/restored/
cleared alongside A3b's registries in `WriteAttemptStateToSave` / `RestoreAttemptStateFromSave` /
`ClearLevelAttemptState`. A mid-level resume brings collected claims back; issued-but-uncollected
sources do not survive, so an uncollected drop can be re-earned.

## For the next agent

1. **`ResolveBossAward` is the single boss rule.** `LevelRewardDirectory.ResolveBossAward(authoredFallback,
   out sourceID)` is used by `BossEncounterController` and `MirrorParadoxEncounterController`. A ledger
   that authors a boss is authoritative (the single 25, once — repeated phases share it, an
   already-claimed source pays nothing); **no ledger, or a ledger with no boss source**, means the
   encounter is not part of that ledger and the authored `BossData` value applies. Do not re-inline
   this at either call site.
2. **`LevelRewardDirectory.SuppressLedgerForTest`** (internal, cleared by `ResetAttempt`) is how a
   synthetic harness level declares it is not a campaign level. Without it a fixture silently
   inherits whichever campaign ledger the previous test left live, every unauthored source in it
   correctly pays nothing, and the failure reads as "the drop system spawned no pickup". Three
   existing tests needed it. Never set it from shipping code.
3. **A7a / B3 handshake.** The Eraser debut still spawns `chrono_guard_elite`, so all nine 4A
   manifests name it. `RewardManifestTests` pins that against `EraserDebutTrigger.PlaceholderEnemyID`,
   so B3's re-point to `EraserEnemyID` **fails this suite by name** — update the nine manifest rows in
   the same change.

## Known gaps (not closed here; also in `docs/DUST_ECONOMY.md`)

1. **No level authors a `SecretCache`**, so the discovery half of every optional pool is allocated but
   unreachable and a thorough run cannot reach 1,000 today. **Level 4A is the sharpest case:**
   `LegacyLevelControllerBase` builds neither a cache nor an Extractor (its own suites assert
   `Extractors.Count == 0`), so 4A's whole 10-dust optional pool has no physical source. Each variant's
   manifest reserves `level_04a_<hero>.secret` for the B wave to attach one to; nothing else changes.
2. **Boss summons can consume a skipped mandatory source of the same enemy ID.** Issuing is keyed by
   enemy ID against a finite queue so the level total is never exceeded, but a summoned
   `chrono_slasher` can draw a mandatory one the player walked past. Closing it exactly needs
   `RewardEligible = false` at the `EnemyAbilityExecutor` summon site — **A7a's file**.
3. **The losses line only ever shows the Collapse fee.** A voluntary pause-menu exit never reaches a
   results screen for its retention fee to appear on.
4. **Banking is unchanged.** The tier bonus is added to the level wallet at completion and banks with
   it at the hub. Moving the deposit itself to level completion was explicitly out of scope.
