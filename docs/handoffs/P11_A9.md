## 1. Shipped

**`FighterStageGeometry` has a floor-segment concept.** The main floor is authored as
`FighterStagePlatform[] FloorSegments` with `SurfaceY = 0` (reusing the platform struct, so
`Supports` / `EdgeX` / `HangPosition` / `IsInCaptureBox` came for free). **An empty array is the
sentinel for "unbroken floor, wall to wall"** — the seven Sealed stages and the legacy flat arena
keep it, so their behaviour is unchanged. New surface:
`HasFloorSupport(FP64 x)`, `IsOpenStage`, `TryGetNearestFloorEdge(x, direction, out edgeX)`,
`RespawnPlatformPosition` (per stage, defaulting to `FighterMatchFlowRules.RespawnPlatformPosition`).

**`TryFindLedge` / `TryGetHangPosition` cover floor segments**, continuing the anchor run at
`(Platforms.Length + segmentIndex) * 2 + side`. **No snapshot field was added** —
`FighterRuntimeComponent.LedgeAnchor` is already an `int` and the component is exactly full at 128
bytes. Both lookups share one private `IsFloorLedge` predicate, so a segment end sitting on a solid
side wall is refused identically by both and a restored snapshot can never resolve a hang the live
tick would not have granted. Landed as one atomic change; the rollback gate re-run is in §4.

**`FighterMovementSystem` floor handling is per-x.**
`HasGroundSupport` (platform surface above y = 0, main floor at y = 0) replaces the old
`Position.y > 0 && !HasPlatformSupport` walk-off check; the ground snap fires only when
`HasFloorSupport(x)`; the drop-through gate passes
`StageHasSolidFloorRule && HasFloorSupport(fighter.Position.x)` so "drop inputs are ignored on the
main floor" holds on segments and cannot re-enable itself over a pit.

**The bottom blast zone is genuinely reachable** on the three Open stages, through ordinary play —
walking off, being launched, or falling in. Audit H-11 closes.

**Per-stage respawn anchors.** `FighterSimulationRules.ApplyStockLoss` gained an optional trailing
`FighterStageGeometry geometry = null`; `ProcessRespawnPlatform` takes the anchor and re-pins it
every tick the platform holds the fighter. Paris respawns at **(−4, 3)** because stage centre is now
a hole.

**Three stage scenes re-authored** — one `StaticBody2D` per floor segment, real pit art with depth
and blast-zone cues, and readable edge cues at every true ledge. See §5 for coordinates.

**`FighterStageConformance.ValidateGroundAndWalls` rewritten for segments** — collects every layer-64
body under `Geometry` that is not `WallLeft`/`WallRight` and matches each against a `FloorSegments`
entry by centre + half-width; a Sealed stage synthesises the single wall-to-wall segment, so the old
contract is the same loop. A scene floor painted across an authored pit now fails.

**Catalog Open/Sealed label (I-13).** `FighterStageData.IsOpenStage` (`[Export]`), set `true` on the
three `stage_catalog.tres` rows, rendered as a badge by `CharacterSelectScreen`'s stage phase and
`HolodeckConsolePanel`'s stage row through the new shared `FighterStageLayoutBadge` key chooser, and
cross-checked against the geometry by a test.

**`CpuDecisionObservation` floor-topology fields + the corrected DI comment** (see §6). Observation
only — **no CPU policy change**, per the plan's split with A9b.

**Docs:** `docs/PACKAGE6_FIGHTER_PLAN.md` §4 gains a `FloorSegments` column plus the V7.6 2.D
provisional-numbers note; §9 gains a full A9 deviation block; the plan's §9 gains the `### A9` block.

## 6. Observation fields A9b consumes

Added to `scripts/FighterSim/CpuDecisionObservation.cs`, filled by
`FighterCpuController.FillFloorTopology` whenever geometry is present:

| Field | Meaning |
|---|---|
| `int HasFloorSegments` | Presence flag for the whole block. **Non-zero only on an Open stage.** Zero on every Sealed stage, the legacy arena, and every Story adapter — this is the field that keeps "closed stages must not trigger false recovery" true by construction. |
| `int HasFloorSupportUnderSelf` | Solid main floor directly under the fighter's X. Always 1 when the floor is unbroken, so **"unsupported over a gap" is `HasFloorSegments != 0 && HasFloorSupportUnderSelf == 0`**. |
| `int LaunchTrajectoryCrossesGap` | The fighter's *current* trajectory ends over a gap rather than over floor. The pit-risk signal for DI and recovery planning. Zero whenever `HasFloorSegments` is zero. |
| `int HasFloorEdgeLeft` / `long NearestFloorEdgeLeftXRaw` | Nearest pit-facing floor-segment end to the fighter's left, raw `FP64`. |
| `int HasFloorEdgeRight` / `long NearestFloorEdgeRightXRaw` | The same, to the right. |
| `long CurrentGapWidthRaw` | Width of the gap the fighter is currently over, raw `FP64`; zero when supported or the floor is unbroken. Exact geometry from the two bounding ends, not an estimate. |

**How `LaunchTrajectoryCrossesGap` is computed:** `FighterCpuController.TrajectoryEndsOverGap` runs a
bounded ballistic probe (`TrajectoryProbeTicks = 240`) forward from the fighter's current position
and velocity, ignoring horizontal input and air control (the question is where the *current*
trajectory ends), stopping at a one-way platform caught from above or at the floor plane. It reads
the simulation's own tick length and gravity through two new `internal` read-only properties —
`FighterMovementSystem.FixedDeltaSeconds` and `.GravityPerSecondSquared` — rather than keeping a
second copy of either number. Pure fixed point, no allocation.

**Story parity is intact.** `MirrorParadoxDecisionAdapter.Observe` (in
`scripts/Enemies/MirrorParadoxController.cs`) leaves the whole block at object-initializer defaults,
the way it already does for `HasStageBounds` / `HasOrb` / `HasHazard`; only its two comments changed
to name the new sentinel. `MirrorParadoxTests`' frame-identical parity is unaffected.

**The DI comment.** `ApplyHitstunDefense`'s XML doc no longer says pit-aware DI is impossible; it now
records that the V7.4 deferral expired with A9, names the fields, and says the policy change is
A9b's. **A9 changed no DI behaviour** — the hold is still toward stage centre on every stage.
