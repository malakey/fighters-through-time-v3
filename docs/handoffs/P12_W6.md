## What shipped

### G04 — display timing
- `project.godot`: `application/run/max_fps=60`, `physics/common/physics_ticks_per_second=60`, `physics/common/physics_interpolation=false` (explicit).
- `FTT.Core.DisplayTimingRules` (in `ViewportEnforcer.cs`) names the constants; `ViewportEnforcer.ApplyDisplaySettings` re-asserts `Engine.MaxFps = 60` on every display apply, so the cap holds with V-Sync on or off.
- Pinned by `DisplayTimingSettingsTests`. The full suite ran at its usual duration with the cap in place (GdUnit does not pump render frames in tests).

### G05 — font slots
- No font file ships with Godot's project templates, so there is **no font asset**. `resources/UI/ftt_theme.tres` now carries `default_font = FontVariation "ftt_placeholder_default_font"` with **no `base_font`** — it renders Godot's built-in face, i.e. the placeholder — and that variation's **empty `fallbacks` list is the reserved CJK fallback slot**. Dropping a face in is: set `base_font`, append the CJK face to `fallbacks`.
- `UIThemeTests.ThemeWorksWithoutAFontResource` was rewritten in place to pin exactly that (slot present, no base font, zero fallbacks).

### G06 — photosensitivity notice + first-launch setup
- `scripts/UI/BootSequenceOverlay.cs` (+ pure `BootSequencePlan`, `BootStep`). `MainMenu` raises it once per process, only when the menu is the **current scene** (the real boot), so hosted test menus never see it (`MainMenu.BootSequenceOverrideForTesting` is the seam).
- Order: notice (every launch, ~3 s, **unskippable until `PhotosensitivityNoticeSeen`**) → first-run cards (only when `FirstRunSetupCompleted == false`) → the G09 crash prompt (Ask only) → menu.
- First-run cards: Reduced Temporal Effects toggle with a placeholder live preview swatch (pulses with the full treatment, steady when On — Package 10 replaces it with the real overlay), UI Scale slider applied live to the theme, controller detection (detected device, Test button with a short rumble and an echo of the next button). **No language card** (EFIGS).
- **Reduced Temporal Effects is still pushed before the first effect**: `SaveManager._Ready` is untouched on that point; the card applies through `ComfortSettings.Apply` the moment it is toggled. Skip restores the defaults.
- `GlobalSaveData.FirstRunSetupCompleted` initializes **true** so an existing payload never sees the cards; `SaveManager.LoadGlobalData` sets it false on exactly the "no global file existed" branch.

### G09 — crash reports (D9(a): no upload)
- `scripts/Core/BuildInfo.cs`: `CrashReportService` arms `user://session_running.marker` at boot (from `ViewportEnforcer._Ready`, the last autoload) and clears it in `ViewportEnforcer._ExitTree`. A surviving marker = previous crash. Separate from `SessionExitGuard`'s campaign marker (same pattern, different scope).
- `CrashReportPolicy.Resolve`: Ask → keep a local report + prompt; Always → keep a local report silently; Never → nothing. The "report" is the crashed session's rotated `godot*.log` copied into `user://crash_reports/crash_<utc>.log` under a build banner; pruned to 5. The prompt offers **Open Logs Folder** (`OS.ShellOpen`), Not Now, Don't Ask Again (sets Never). **No network code exists anywhere.**
- `project.godot`: `debug/file_logging/enable_file_logging=true`, `max_log_files=5`, `log_path=user://logs/godot.log`.
- About & Privacy is a section **inside the Gameplay tab** (D9(a)): heading, build version, plain-language privacy notice, the Crash Reports dropdown and an Open Logs Folder button.

### G10 — Text Speed + Dialogue Log
- `TextSpeed { Slow=0, Normal=1, Fast=2, Instant=3 }` and `TextSpeedRules` (20/30/60/∞) in `FrontEndSettings.cs`. `DialogueRevealModel.SetSpeed`; punctuation holds scale by `30/rate` (Slow 1.5×, Fast 0.5×), chirp cadence scales to stay ~10/s, Instant lands the line at once silently. `DialogueRevealModel.CharactersPerSecond` is still 30 as the Normal default (the existing pin holds). `DialogueManager` reads `GlobalSaveData.DialogueTextSpeed` at sequence start.
- `DialogueLog` (static, session-only, 100-line ring, **never saved** — no payload references it) and `DialogueLogScreen` (overlay, never touches the pause). Fed in `DialogueManager`: each line on show, and on `EndSequence` every not-yet-logged line (the confirmed-skip path; `FromSkip = true`). Opened from the Story pause menu (`LogButton`) and during dialogue by a `LogButton` in the skip-hint row or the new **`ui_dialogue_log`** action (Tab / joypad right-stick click; a UI action, no `GameplayButtons` bit, not a Controls row). While the log is up the reveal, hold-to-skip and auto-advance are held.

### G11 — auto-pause + Mute When Unfocused (D7(a))
- `PauseMenuBase` now pauses on `NotificationApplicationFocusOut` via `HandleFocusLost()` (no-op when already paused or when `CanAutoPause()` — default `CanTogglePause()` — refuses). Regaining focus never resumes. Because every pausable surface derives from it, this covers Story levels, the hub, local Fighter, the Holodeck and the Calibration Drills. The subscription lives in `_EnterTree`/`_ExitTree` so a subclass `_Ready` cannot skip it.
- Controller loss in Story and the hub: `PauseMenu` subscribes to `InputManager.PlayerDeviceDisconnected` (player 0), opens the pause with a `ControllerNotice`, and any face button from a connected pad rebinds player 1 and resumes (`ResolveControllerLost`). Resume also works. `LocalFighterPause` already handled controller loss and was not edited (W5 owns it).
- `FTT.Core.PlatformOverlay` / `IPlatformOverlay` / `NoOpPlatformOverlay`: the Steam overlay seam. **Invoked nowhere real.** `PauseMenuBase` listens to `PlatformOverlay.OverlayActivated`.
- `AudioManager`: Mute When Unfocused (default On) mutes Master only while focus is lost (`ResolveMasterMute`).

### G13 — Block Mode + stick processing (D8(a))
- `BlockToggleLatch` (pure) runs inside `InputManager.SampleGodotDevice` **before the chord recognizer**, so a latched stance is simply "Block held" to the grab chord, the tech/escape reads and the sim. Block press toggles; the player's own Jump or Roll press releases on that frame; a grab chord formed while latched releases next frame; charge depletion is left to the sim's empty-shield refusal. Latches reset on device reassignment and on a mode switch. CPU/override input sources are never latched.
- **Consequence to know:** in Toggle mode the Echo Step *chord* (Block+Roll) is unreachable from a latch, because Roll is an exit. Echo Step stays reachable through its direct binding or Hold mode.
- Stick profiles: `GlobalSaveData.StickProfiles` keyed by joypad GUID with a `"default"` entry. Left-stick radial inner deadzone with rescale (0–40 %, default 15 %) feeds every left-stick action; Down from the left stick reads against the down threshold (default 50 %); digital Down is unchanged. All before quantization; never in a snapshot or hash. `InputManager.BlockModeOverrideForTesting` is the seam.

### M27 — Settings
- Tabs unchanged in order (Audio, Display, Gameplay, Controls — the existing suite pins that order; the GDD lists Controls before Gameplay, a presentation-only difference recorded in §9).
- Audio: `settings_ui_volume` value is now "UI & Dialogue Volume"; it drives the UI bus, which the Dialogue bus sends into, so one gain reaches both without double attenuation. Four mute toggles (Master/Music/SFX/UI&Dialogue) + Mute When Unfocused. `AudioManager.SetCategoryMuted` accepts only the four category buses: **`CriticalCues` and `Dialogue` are never muted, re-routed or bypassed**; they follow the category through their sends, which is C01b's "clear routing respects the category mute".
- Vibration toggle + intensity moved to `Controls/Options` (alongside Block Mode, the device selector, Deadzone and Down Threshold).
- Settings stays reachable from the main menu, Story/hub pause and Fighter pause (unchanged openers).

### G14 — lower difficulty from the hub
- `StorySaveData.LowestDifficultyUsed` (additive; initializer **Hard**, so `CampaignDifficultyRules.EffectiveLowest = min(field, Difficulty)` reads a pre-field payload as its own tier with no engine work). `CreateStorySlot` seeds it from the starting difficulty. **No save-version bump.**
- `CampaignDifficultyRules.Evaluate` (pure): hub only, not in a parked mid-level attempt (`LastCheckpointID` set or a pending Timeline restart), not in the Act III gauntlet, not after completion, never below Easy. `CampaignDifficultyService` commits one step to the save **and the session**, then `SaveStorySlot`.
- UI: a `LowerDifficultyButton` in the Story pause menu, **visible only in the hub when allowed**, behind a `ConfirmModal`. I put it in the pause menu rather than a hub node so `HubWorldController` (W2/W7) is not edited at all.
- Read checks: `StoryManager.BeginLevelRun` (fresh entry) refills the rewind pool and `MintFreshAttempt` sets Act III anchors from `session.Difficulty`; `StoryDifficultyTuning.CurrentStoryDifficulty` reads the session. A resume restores from the save and does not re-initialize — which is why a parked attempt refuses the change. Nothing is retroactive.
- Slot card shows "Lowest difficulty used". Results screen / campaign-complete banner were **not** done.
