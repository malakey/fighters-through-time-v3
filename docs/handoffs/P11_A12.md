### Expected-to-fail until the orchestrator's `--headless --import`

A12 adds 25 rows to `localization/en.csv` under `# Package 11 A12`, and per §2.11 the
regenerated `localization/en.en.translation` is deliberately **not committed**. Against
the committed tree these **three cases fail**, and only these three — all of them assert
through the compiled table, so their "missing from localization/en.csv" wording is
misleading; the keys are in the CSV:

1. `Level04AEinsteinContentTests.TheDialogueSetResolvesWithTheThreeBeatsAndEveryLineKeyLocalized`
2. `Level04AEinsteinContentTests.EveryVisibleLevelStringHasALocalizationEntry`
3. `CampaignRouteTests.EveryCampaignRouteSlotHasAUniqueLocalizedHubMissionName`

All three, and the full 127-case sweep below, were **verified green in this worktree with
the translation reimported**; the binary was then reverted for the commit. A fourth gate,
`CampaignLocalizationTests`, resolves the same keys but reads the CSV for its floors and
stayed green either way — re-check it after the import regardless.

**Import caveat worth knowing.** `--headless --import` regenerates `en.en.translation`
only when `en.csv` looks *changed* to Godot's import cache. Reverting the compiled binary
without touching the CSV leaves the cache saying "already imported", so the import silently
no-ops and the stale binary survives — which reads exactly like a missing key. If that
happens, `touch localization/en.csv` and reimport. The orchestrator's wave merge changes the
CSV content anyway, so this only bites when reverting the output alone.
