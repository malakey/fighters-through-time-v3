# GR-AUDIO handoff (gameplay review package, 2026-11-03)

Branch `gr/audio`. Ruling 13 (a small hit-sound set before the human session: hit, block, perfect block, grab, whiff, KO, Defy, wind-up; volume-capped, separately mutable, placeholder until Package 10; amends the 2026-08-10 silence directive for these cues only); plan section 2, GR-AUDIO; dossier E section 13. **Nobody has played, heard or looked at any of it.** Every claim is a headless suite, and the sounds themselves have never been listened to: the synthesis was checked only by numbers (length, peak, the content tests).

## What shipped

**Assets** (`tools/generate_placeholder_audio.py`, original numpy synthesis, no third-party material, seeded noise so a regenerated file byte-matches):
- `ASSETS` is now `path -> (builder, audible)`; the module-level `RENDER_SILENT` is gone. Audible assets are scaled so their peak is exactly `AUDIBLE_PEAK_CEILING` 0.3 (all seven new ones and the stinger hit it); silent ones are zeros of the builder's exact length, as before. `main(argv)` writes only the named files when given names, and always rewrites the manifest.
- Seven new files under `audio/sfx/combat/` with `.import` sidecars: `hit_basic` (0.09 s: low-passed noise burst over a fast-dropping 180 Hz body), `block` (0.12 s: inharmonic metallic ping on a click), `perfect_block` (0.20 s: a brighter ping with two beating high partials), `swing_whiff` (0.14 s: a falling band-pass noise sweep), `grab_catch` (0.14 s: grip noise, 95 Hz thud, a faint buckle tick), `defy_burst` (0.45 s: crack, falling sweep, three-partial bell), `ultimate_windup` (0.33 s: a rising 300 to 950 Hz sweep with a 22 Hz flutter). `ko_stinger.ogg` was regenerated audible (scaled down to the 0.3 ceiling); the other four generated `.ogg` files (victory fanfare, countdown blip, rewind sweep, clock tick) and every `.tres` payload stay silent and were not rewritten.
- `audio/sfx/placeholder_cue_manifest.json` (new, generated): per asset `audible`, `peak`, `seconds`. A Vorbis stream cannot be decoded in the test host, so the content tests read this.

**Catalog** (`resources/Audio/core_mechanic_cues.tres`, `CoreMechanicCueCatalog.cs`, `CoreMechanicCueEntry.cs`):
- Four new rows `hit_basic`, `block`, `perfect_block`, `swing_whiff` (Combat bus, not Critical), IDs `CoreMechanicCueIDs.HitBasic`, `Block`, `PerfectBlock`, `SwingWhiff`, added to `All` (the catalog is now 30 rows; `Critical` is unchanged).

- `CoreMechanicCueEntry.VolumeDb` (additive export, default 0) and `MinIntervalSeconds` (additive export, default 0). Every audible row is `VolumeDb = -12.0`. Throttle windows: hit 0.09 s, block 0.12 s, perfect block 0.15 s, whiff 0.15 s; the reused rows are unthrottled.
- `CoreMechanicCueIDs.AudiblePlaceholders` (nine rows) and `IsAudiblePlaceholder(id)`.

**Presenter** (`CoreMechanicCuePresenter`): `Play` now checks `AdmitRow` (the mute for audible rows, then the row's throttle) and routes with `entry.VolumeDb` on both the ordinary and the Critical path (`PlayCriticalCue` already took a volume). `Play` still returns true for an existing row that the throttle or mute dropped. ## Deviations from the plan
- `ko_stinger_decisive` is also an audible placeholder (nine rows, eight assets). It shares `ko_stinger.ogg`, and the stock-loss branch skips the plain stinger when the match is complete, so without this the match-ending KO would have been silent while every other KO sounded.
- The rows `grab_catch`, `defy_burst`, `ultimate_activation_windup` and `ko_stinger` also carry -12 dB, though the plan names -12 only for the new rows: the ruling says "volume-capped", and these are the same kind of stand-in sound.
- A second additive entry export, `MinIntervalSeconds`, holds the per-cue throttle in the catalog (one value, in the `.tres`) instead of a table in code.
- The Fighter edges for hit, whiff and block are value edges (HP falling, a phase passing Active, a charge falling), not wrapping counters: the sim has no counter for them and may not gain one. `IsForwardCounterStep` still guards the one that has a counter (the perfect-block count, already in `SyncPerfectBlockFlash`, from which the cue now plays). A correction that lowers a value plays nothing; a correction that removes a presented hit and re-adds it later at another tick can play its thump twice, bounded by the row's throttle window (as the damage flash behaves; LAN is de-scoped).
- The Story hero being hit plays no cue (the dossier names the landed path of the hero's own hits). Fighter has no way to tell who hit whom from an HP edge, so there the thump plays when either fighter takes non-hazard damage.

Peak ceiling 0.3 and every row at -12 dB; the throttle windows 0.09 / 0.12 / 0.15 / 0.15 s; the durations (0.09 to 0.45 s) and every synthesis constant in the builders; the nine-row audible set; one Settings label.

## Known limits
- Zone and damage-over-time ticks in the Fighter sim drop HP too, so they play the hit thump (thinned by its throttle); Story's ticks confirm nothing and play nothing.
- Pitch and variation: none. Repeated hits are the same sample.
- The Critical-path cues (Defy, wind-up, KO) obey the placeholder mute; the C01b rule (a category mute never silences them) still holds for the real mutes. Muting skips only the sound: `PlayDefyBurst` still applies the `DefyOrScripted` snapshot.
- `localization/en.en.translation` was not committed (orchestrator). `SceneVisibleTextTests` needs the compiled key `settings_mute_placeholder_cues`; it passed in this worktree with a locally compiled translation that was then discarded, so expect that suite to fail on a tree that has the new `Settings.tscn` row without `--import`.
- Nobody has listened to the cues, set their balance against the real mix, or checked them on a pad session, a swarm wave, or the Settings row at UI scale 1.4.
