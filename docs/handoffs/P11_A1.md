## 1. What shipped

### 1.1 One status data contract — `scripts/Combat/StatusSlots.cs` (new, exclusive)

- `enum StatusSlot { Damage = 0, Control = 1 }`
- `struct StatusEffectData { StatusType Type; float RemainingSeconds; float Intensity; }`
  (+ `IsActive`, `Empty`)
- `struct StatusSlots { StatusEffectData Damage; StatusEffectData Control; }`
  (+ `this[StatusSlot]`, `Has(type)`, `Active`, `Empty`)
- `static class StatusRouting` — the **one** routing implementation:
  - `StatusSlot SlotOf(StatusType)` / `SlotOf(int)` — the compile-time table.
    Damage: `Venom`, `RadiantBurn`. Control: `TimeDilation`, `StaticCharge`, `Root`, `Suppression`.
  - `bool IsDamageSlot(StatusType)`
  - `bool ShouldReplace(current, currentIntensity, currentRemaining, incoming, incomingIntensity, incomingDuration)`
    — the Story-side stronger-wins rule.
  - `bool ShouldReplaceRaw(currentType, currentIntensityRaw, currentFrames, incomingType, incomingIntensityRaw, incomingFrames)`
    — the fixed-point sibling. Exact `int64` product of the FP64 **raw** intensity and the integer
    frame count; no division, no float, bit-reproducible across a rollback. **Callers must pass
    already-normalized raw intensities** (the sim's `ApplyStatus` substitutes `FP64.One` for a
    non-positive authored intensity before storing, so this holds).
- `interface IStatusEffectTarget` — `ActiveStatuses` (get/set), `ApplyStatusEffect(type, duration, intensity)`,
  `ClearStatusEffect(StatusSlot)`, `ClearAllStatusEffects()`, `Node2D TargetNode`.

The file is deliberately free of a `using Godot;` — the simulation calls `SlotOf` and
`ShouldReplaceRaw` on its hot path. `StatusController.IsDamageStatus` is retained as a **forwarder**
to `StatusRouting.SlotOf`, so A8 can keep deriving the HUD slot from it and the sim's existing
signature is unchanged.

### 1.2 Stronger-wins at all four sites

Within a slot: a different type always replaces; the same type replaces only when
`newIntensity × newDuration >= currentIntensity × currentRemaining`, bringing its own duration; a
weaker same-type application is a **complete no-op** (no replace, no refresh, the occupant keeps its
own remaining time); the other slot is never touched.

|---|---|
| `StatusController.ApplyStatus` | `scripts/Combat/StatusController.cs` |
| `EnemyController.ApplyStatusEffect` | `scripts/Enemies/EnemyController.cs` |
| `BossController.ApplyStatusEffect` | `scripts/Enemies/BossController.cs` |
| `FighterDamageRules.ApplyStatus` | `scripts/FighterSim/FighterEntitySystems.cs` |

### 1.6 F07 double-stun fix (`EnemyController`)

`OnHurtboxHit` now computes
`concurrentStun = staticChargeRidesThisHit ? max(hit.HitstunDuration, hit.StatusDuration) : hit.HitstunDuration`
and calls `ApplyStun(concurrentStun, minimumSeconds, fromSpecial: AttackClass == Special)` **once**.
The status then applies through the new
`ApplyStatusEffect(type, duration, intensity, fromHitPayload: true)` overload, whose `StaticCharge`
arm skips the second `ApplyStun`. Consequences fixed:

- Tesla's finisher charges **0.4 s** of elite stagger budget, not 0.8 s.
- `_stunTimer` takes the **max**; a short Static Charge can no longer shorten a floored basic-string
  stun.
- A special-sourced Static Charge is classified `fromSpecial`, so it diminishes and refreshes the
  4.0 s window.
- `ApplyStatusEffect` **refuses** `StaticCharge` while `IsStaggerArmored`, and
  `BeginArmoredRecovery` clears a live `StaticCharge` control slot — the lock cannot persist behind
  stagger protection.
- The three-argument public overload is unchanged, so direct callers still route their own stun.

## 3. What was NOT delivered, and why

1. **`IStatusEffectTarget` does not inherit `IDamageable`.** `IDamageable` does not exist anywhere in
   the repository (`grep -r IDamageable` → no hits), contrary to dossier E §2.3's "IDamageable exists
   in the repo". Inventing one means retrofitting the whole hit pipeline; the interface is declared
   standalone with all five specified members. Recorded in §9 for a future extraction package.
2. **`BossController` did not need status slots built** — it already had them (the dossier and plan
   both say otherwise). The delivered work was re-expressing them over the shared contract.
3. **`FighterConductiveRules.TryConsumeChain` has no sim consumer.** It is implemented and pinned
   (including a snapshot/restore replay) because the design requires component 318 to carry
   consumed-attack state, but the sim has no bespoke multi-hit Lorentz Pulse today — Tesla's
   Special 2 runs the generic zone path. Whoever ships one must route its chain decision through it.
4. **The HUD cross-out and the Conductive circuit glyph are A8's**, per §3 A1 item 8/9. A1 exposes
   the state (`IsAbilityCastSuppressed`, `IsAuraSmothered`, `ConductiveFramesRemaining`,
   `ConductiveSourcePlayerID`) and publishes `OnAbilitySlotLockChanged`.
5. **`StatusController.ClearSlot`'s "re-announce the survivor" hack is still in place**, as
   instructed; `StatusEffectPayload` gained no slot discriminator. A8 deletes the hack once two pips
   exist.
6. **`resources/Enemies/*.tres` are untouched.** The Eraser and its Null Lance are A7a's; A1 only
   provides the status they will apply.

   slot **stronger-wins** — a different type always replaces, the same type only when
   `newIntensity × newDuration >= currentIntensity × currentRemaining`, and a weaker same-type

   no action lock and contributes zero stagger budget. Lorentz chains gate on the mark.
5. **V7.4 Enemy Stagger Discipline bullet** — amend: a hit carrying both hitstun and a Static Charge
   now runs them concurrently and charges the budget **once** with the greater duration; armor
