## 1. Shipped

**The F19 tiered recovery planner replaces the inverted percentage ladder.** `DecideRecovery` was
jump → movement → Special 2 with `RecoveryMovementPercent = 0` and `RecoverySpecialTwoPercent = 55/85`
on Easy and Medium — the exact inverse of the contract, which makes the movement ability Easy's one
permitted tool and Medium's default and forbids Specials on Easy outright. It is now:

- **Easy** — steer at the nearest legal landing, spend remaining jumps, **one** movement-ability
  activation per offstage episode, no Specials anywhere.
- **Medium** — estimate reachability with the jumps in hand (`JumpsAloneCanReturn`), otherwise **one**
  suitable ability, the movement ability by default. No multi-ability or platform/refund chains.
- **Hard** — route comparison (`PlansMultiActionRecovery`): opens with the ability when jumps alone
  cannot cover the gap, chains where the kit actually refunds, re-evaluates every decision, and past
  `OffstageStallLimitFrames` (240) drops every optional hesitation so it cannot stall offstage.

**An offstage `episode` latch, input-side, outside the rollback snapshot.** `_episodeActive` opens
when the fighter first becomes unsupported over a gap or past a wall and ends only on a stable
landing on **authored** stage geometry (`IsStableStageLanding`: floor support under this X, or
standing on one of the stage's own one-way platforms), a legal ledge capture, or a KO — so a jump
refund or a temporary staff-platform landing does not reset the one-activation limit, exactly as the
contract requires.

**The activation is charged at delivery, not at decision.** The 128-slot schedule ring can overwrite a
pending slot under Easy's 30–45-frame jitter; charging at decision time meant Easy spent its single
activation on a plan that never reached the simulation and then emitted **zero** movement-ability
presses for the rest of the episode. `_movementActivationDeliveryTick` marks the in-flight plan,
counts against the cap so two can never be queued, and is released (not charged) if its tick passes
unconsumed.

**Recovery detection is "unsupported over a gap."** `IsOffStage` keeps the past-a-wall branch and, on
Open stages only, uses A9's `HasFloorSupportUnderSelf == 0 || LaunchTrajectoryCrossesGap != 0`. A
Sealed stage has `HasFloorSegments == 0`, so the gap branch is unreachable there — the contract's
"closed stages and ordinary supported traversal must not trigger emergency casts" holds by
construction, with no Y threshold.

**`CpuRecoveryProfile` (new file, `scripts/FighterSim/CpuRecoveryProfile.cs`)** — the nine
per-character profiles, code-owned like `CpuBandTuning` because Fighter Mode stays competitively
normalized. It is built from the CPU fighter's own normalized `FighterLoadout`
(`FighterSimulationDriver` passes `CpuRecoveryProfile.FromLoadout(FighterLoadoutFactory.FromCharacterData(_playerTwo.Data))`),
so every distance, duration, cooldown, jump force and air-control value it plans against is the
authored one — no duplicated tuning. `AimMovementAbility` aims the way the shipped simulation reads
each authored `MovementType`: Blink/Teleport/Warp translate along the held stick (and the sim applies
the authored distance per axis independently, so a diagonal hold is strictly better), while
Glide/Dash/Float launch along facing, which the return steer has already been turning toward the
stage.

**Pit-aware DI; the V7.4 deferral is closed.** `ResolveDiHold` aims at the nearest pit-facing floor
edge while the launch trajectory ends over a gap, and keeps the unchanged toward-centre hold
everywhere else. On Paris that is the difference between DI and suicide — stage centre is the hole.

**CPU grabs and Echo Step, emitted as the shared chords a human presses.** Easy uses neither. Medium
takes the contract's provisional 25% admission for both. Hard scores both (`ScoresGrabTactically`
requires a throw that actually improves position; `ReservesMeterForDefy` weighs the 30-meter spend
against a viable Ultimate setup and an unused, eligible Defy, and still spends it against a credible
punish). Admission is rolled **once per opportunity** — `_grabOpportunityID` for grabs,
`_attackExecutionID` for Echo Step — and a failed roll never reopens a continuing opportunity.
`ScheduledDecision` carries the intended verb and `VerbStillLegalForSelf` drops it at delivery if the
CPU's own state has lapsed; opponent conditions are deliberately not rechecked, because the contract
says a planned grab is allowed to whiff. While a grab holds, the stick *is* the throw choice — held
toward the nearer useful stage edge or pit edge, forward/back resolved by the shared
`FighterGrabRules`, deterministic tie-break to the right edge.

**Echo Step destination safety is checked before selection**, including pit risk, walls, the blast
zone and active hazard bands, via the exact historical destination rather than a substitute.

**Observation additions (`CpuDecisionObservation.cs`, A9-owned, additive).** A self verb block behind
`HasVerbState` and a target block behind `HasTargetVerbState`, plus the resolved Echo Step
destination. Both are filled only when an `ICpuWorldObserver` can resolve a `FighterVerbComponent`,
which the Story adapter cannot — so the F19 branches are unreachable in a campaign level by
construction, exactly like the stage/orb/hazard/floor blocks. The two new `ICpuWorldObserver` members
are **default interface methods returning `false`**, so every existing implementer (including the
test fakes) compiles untouched.

## 2. Not delivered, and why

- **The Mirror Paradox does not gain grabs or Echo Step.** `CPU_COMBAT_POLICY.md`'s F20 paragraph
  routes that through `MIRROR_PARADOX.md`, which is **A7b's** dossier. The Story adapter has no verb
  layer to project; the sentinels keep the branches inert until one exists. My mandate was that
  `MirrorParadoxTests` stays frame-identical, and it does.
- **No character approves an optional mobility Special.** Pocahontas's Spirit Strike — the only
  candidate the contract names — is **rejected after validation**: the shipped simulation translates
  the caster only inside `FighterAbilitySystem.ApplyMovement`, and `pocahontas/special_1.tres` is
  `ExecutionType = 0` (Melee) with no caster translation, so the design's forced diagonal-up dash is
  unimplemented. The contract's own fallback applies. Ledger row `VERIFY-CPU-MOBILITY-SPECIALS`.
- **`DEFER-CPU-SNAPSHOT` is opened, not resolved.** `CPU_COMBAT_POLICY.md` asks for the admission
  result, opportunity IDs and PRNG state to be snapshotted for resimulation. The controller is an
  input source outside the rollback snapshot by design (Package 6 §2.5); its frames are recorded and
  replayed, so rolls are never re-sampled. Satisfying the document's letter would make CPU frames
  simulation-derived, which is the architecture Package 6 rejected. Ledger row carries the acceptance
  criteria. **Do not "fix" it by re-sampling during resimulation.**
- **Dedicated wire bits.** A1c adds `gameplay_grab` / `gameplay_echo_step` with protocol-v3 bits in
  parallel. A9b emits through the input path the sim accepts on this base — `Block` + a `BasicAttack`
  edge for the grab, `Block` + a `Roll` edge during the swing's recovery frames for Echo Step. **A1c's
  bits are the follow-up**; the CPU already emits a logical verb, so the chord constants in
  `TryDecideGrab` / `TryDecideEchoStep` (and the two `Is*Chord` helpers in `CpuVerbPolicyTests`) are
  the only things that move.
- **Paris's deep-centre pit is not recoverable for Lincoln on any tier** and is recorded rather than
  papered over. Ledger row `VERIFY-PARIS-DEEP-PIT-RECOVERY`; the committed drill uses the shallow
  knock the contract's "basic route" language covers.
