## What shipped

### M16 — Act III stand-ins become Interact channels
`ResonanceHoldNode` no longer has HP and no longer discharges.
- `DamageableEnvironmentObject` gained `AcceptsEnvironmentDamage`, so hurtbox hits and direct kit arcs (Tesla's Resonant Overdrive) both apply nothing.
- Its `_PhysicsProcess` replaces the Extractor's idle cycle outright.

**The channel.** The player holds Interact for `ChannelFrames` = **180** at up to `ChannelRangePixels` = 130. The Restoration Font's range-anchored channel is the precedent.
- It starts through the shared `InteractionArea`. The node builds one in code if the template has none, and the prompt is `hold_channel_prompt_{conduit,valve,pylon}`.
- It **resets** (it does not pause) on any HP loss, leaving range, releasing Interact, stun, daze or death, Time Freeze, the Post-Landing Hold, `ChronalRewindManager.IsWorldHeld`, or a rewind freeze. It cannot start in any of those states.
- Integrity keeps draining throughout.
- A `RadialProgress` child shows the fill. Only the node writes to it.

**Completion** calls the new `CompleteWithoutDamage()`, so it runs the ordinary Extractor destruction path exactly once:
- the drain-factor drop;
- the F05 allocation for its stable `ObjectID`, spawned as a physical pickup;
- `RecordExtractorDestroyed`;
- the variant's "drain slowed" notice, via a new `DrainSlowedNoticeKeyBase` hook.

The `chronal_extractor` group and the F01 starting denominator are unchanged. A completed node keeps its state through a death rewind (`PreserveCurrentState`).

**Pre-existing bug fixed in passing:** `ChronalExtractor.OnDestroyed` no longer lowers the living count a second time when a machine that a death rewind restored to its checkpoint HP is broken again.

### GAP-03 — secret caches
- `SecretCache.Discover()` now issues the level's reserved `{level}.secret` F05 source once, as a physical pickup (`DustAwardSource.Secret`). The wallet is paid, and the results line attributed, only at collection.
- `RestorePendingAward()` covers a resume that finds the secret already found but its pickup never collected: the reload discarded the pickup, so the source re-issues once. A claimed source never pays again.
- An unledgered context counts the secret but pays nothing.
- `StoryLevelControllerBase.BuildAuthoredSecretCache()` runs right after `BuildLevel()`, so the sealed 4A `BuildLevel` gets a cache too. The position is a per-level `SecretCachePosition`, which is `abstract` on `LegacyLevelControllerBase`. `SecretSourceID` = `{DialoguePrefix}.secret` matches every manifest.
- Placements cover Levels 2–15 and all nine 4A variants. Level 1 reserves no secret by design.
  - Each cache is centred 95 px above an existing platform, off the critical path, and at least 300 px from every checkpoint and the spawn.
  - Each is outside every boss or Mirror reveal radius. In 4A, each is on the room-1 upper ledge, before any kit gate.
  - Each is reachable with the worst character's double jump (Lincoln, about 124 px per jump). Every hop is at most about 230 px up with a gap of at most 250 px.
  - No geometry was added. The per-level table is in the sub-agent section below.

### GAP-05 / N01 — the sealing anchor (D12(a): AwaitingSeal is persisted)
- **The anchor.** `TemporalCoreAnchor` is generalised into the reusable sealing anchor:
  - `CreateSealingAnchor(id, position)` builds the column, the signage (`seal_anchor_dormant` / `_ready`) and the interaction box, with prompt `seal_timeline_prompt` = "Interact: Seal Timeline — Complete Level".
  - `CanInteract` refuses a dead hero, Time Freeze, the Post-Landing Hold and `IsWorldHeld`.
  - It takes a single press: no hold, meter, confirmation, healing or invulnerability.
- **The shared rules** live in `FTT.Environment.SealReadiness`: `IsPreSealLoad`, `CommitDefeat`, `NoteBossPickupCollected`, `ClearOnCompletion` and `RestorePendingBossPickup`.
- **The flow in `StoryLevelControllerBase`:**
  1. Boss defeat commits `sealReadiness` as an F10 critical event: `BossDefeated`, the stable `{prefix}.sealing_anchor` ID, and `PendingBossPickup` while the boss source is unclaimed. It grants no completion, deposit or unlock.
  2. The existing post-boss beats play.
  3. `EnterAwaitingSeal()` arms the anchor and posts `seal_timeline_objective`.
  4. The player's Interact calls `AcceptSeal()`:
     - remaining Extractors take `ShutDownBySeal()` — terminal, inert, damage refused, no pickup, registry entry, drain change or notice;
     - then `CommitLevelCompletion()` (readiness cleared, `OnLevelComplete` raised once);
     - then a `seal_timeline_sealed` notice;
     - then the exit beat, which serves as the restoration vignette;
     - its end presents the results.
- **Completion commit split from presentation.** `ShowCompletionResults()` no longer commits and presents in one step, so the commit always lands **before** the vignette. Completion stays one-shot.
- **Pre-seal load.** This is detected before `BuildLevel`: a live attempt whose `sealReadiness.BossDefeated` names this level, and a save parked in its scene at a checkpoint.
  - The boss encounter is built with `SpawnOnReady = false`, so the boss is never respawned.
  - `IsBossDefeated` is true.
  - The anchor is re-armed.
  - An uncollected boss reward respawns once as its Large pickup. Claims persist and issues do not; a claimed source spawns nothing and clears the flag.
- **Coverage:**
  - Levels 2–14 and all nine 4A variants use the generic anchor. Its position is derived as boss spawn + (−260, 0).
  - **Level 1 (Florence)** predates the base, so it is hand-wired through `SealReadiness`: defeat commits readiness, the anchor arms after the 1.5 s beat, and the seal commits before `level_01.exit`. Pre-seal load is supported there too.
  - **Level 13** routes the Mirror through `CommitNonStandardBossDefeat()`. The anchor sits at `MirrorSpawnX − 260` on the shelf, and a pre-seal load never stands the Mirror up.
  - **Level 15** keeps its scene-authored Prime Anchor (`UsesGenericSealingAnchor = false`, `SealingAnchorID = PrimeAnchorID`) and persists and restores readiness through the base.
  - The Package 11 rule "a quit between the boss and the Core repeats the fight" is retired.

### GAP-08 — Reset Puzzle (sub-agent, commit `dd94723`)
- **The station.** `PuzzleResetStation` is an `IInteractable`, prompt `interaction_reset_puzzle`.
  - It reconstructs **unsolved** puzzles only. A puzzle solved live, or recorded in the save's completed-puzzle list, makes the station inert.
  - It refuses during Time Freeze and the hold, on a duplicate same-tick press, and inside a physics flush.
- **Geometry validation.** Every prop's collision shapes are tested at its authored home with `Shape2D.Collide` before anything moves.
  - Players, enemies, constructs or a foreign puzzle's weight obstructing a home refuse the **whole** reset with a `puzzle_reset_obstructed` notice. Nothing moves, so there is no partial reset.
  - A lost or freed prop is recalled or rebuilt once under its `PropID`.
- **Ownership.**
  - `WeightedObject` gained `PropID`, `PuzzleOwnerID` and `AuthoredHome`.
  - `PressurePlate` gained `AcceptedPuzzleOwnerIDs`. An empty list keeps the old behaviour; a non-empty one rejects foreign and unowned props.
  - `PressurePlate` also gained `AcceptsPlayerOccupancy`, default true, which keeps today's `PlayerWeight`. Pompeii's east pan needs the hero's weight.
- **`PuzzleManager`** gained an unsolved-only arrangement reset path. `ResetPuzzle` is unchanged.

### M10 — Orléans volley cover (implemented; no acceptance needed; sub-agent)
- `VolleyCover` is a `Node2D` child of a `StoryCyclicHazard`. A player whose feet are inside its rectangle during the Active phase takes no damage **from that hazard only**.
  - The default rectangle is 72×110, plus 8 px below the ground line.
  - The rule is deterministic and area-based: no raycasts and no randomness.
  - Jumping above the cover exposes the player.
  - Stepping out of cover mid-volley is still a hit, because the cycle's hit is not spent while sheltered.
- Level 2 authors a non-solid mantlet in each of the six mortar lanes, so the route works for every hero on basics.

### Shape-query specials (sub-agent)
- `FTT.Combat.StoryShapeQuery.DeliveryMask(targetLayer)` returns `targetLayer | PersistentObject` (= the slot's Hitbox mask). 19 kit sites use it.
- The exceptions are the zero-damage displacement queries (the Tempest push and the tornado lift) and the four constructs' target-acquisition queries.
- A source sweep fails on any new bare-mask damaging query.
- `Hurtbox.TakeHit` now also discards a player-sourced hit on a non-player target during Time Freeze. Before, the freeze gate existed only in `Hitbox.OnAreaEntered`, so shape-query deliveries bypassed it.

### Architecture
- `StoryLevelControllerBase.IsActIII` is deleted. It had zero consumers and was also true for `LegacyNexus = 16`.

## Deviations
1. **The seal prompt is static text** ("Interact: …"), not a live C01c binding glyph. The repository has no binding-display helper.
2. **The restoration vignette is a placeholder:** the level's existing exit dialogue plus a world notice. Level 14's local-objective copy and the Act III destination wording are unchanged.
3. **The Level 1 seal is hand-wired** (it does not extend the base), sharing only `SealReadiness`.
4. **Level 15 keeps its own anchor and arm timing:** it arms at defeat, before its post-boss beat, as in Package 11. Only persistence was added.
5. **Level 13's anchor** is offset from the Mirror spawn. Its position cannot be derived because the Mirror is not a `BossEncounterController`.
6. **Every solved Strike gate now drops `EnemyHurtbox`,** not only the old effigy's.
7. **The Time Freeze discard was added in `Hurtbox.TakeHit`,** so shape-query deliveries obey the freeze. This applies to enemies too, consistent with V7.6.
8. **A boulder on `Environment`** now stops enemy projectiles, and phasing enemies pass it while chasing.
9. **M16 channel constants are provisional:** the 130 px range and the reset-not-pause rule. The design gives the 180 frames and nothing else numeric.
10. **A sealed Extractor refuses all damage,** so it cannot be broken afterwards for a late pickup.
11. **Pompeii's broken wedge is not restored by a reset,** because breaking it is a release, not a losable state. A reset pumice falls onto the east pan instead.
