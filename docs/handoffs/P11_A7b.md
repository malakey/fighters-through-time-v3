### 1.3 F20 Mirror Paradox campaign AI profile (dossier item 3)

- **Tier from the Story difficulty, latched once at spawn.** `MirrorParadoxController` reads
  `StoryDifficultyTuning.CurrentStoryDifficulty` into `EncounterDifficulty` and maps it to
  `EncounterCpuDifficulty`. `MirrorParadoxDecisionAdapter`'s constructor now takes a
  `CpuDifficulty` — the hardcoded `CpuDifficulty.Hard` is gone. The saved Holodeck `CpuDifficulty`
  is never read anywhere on this path, so that independence is structural.
- **Boss-override band.** The adapter builds its engine with
  `CpuBandTuning.BossOverride(difficulty)` through the pre-existing `tuningOverride` seam. New
  `CpuBandTuning.EasyBoss` restores the full core kit on Easy (`Easy with { … }` lifting
  `SpecialOneClose/Ranged`, `SpecialTwo`, `MovementAbility`, `ApproachJump` and the Ultimate policy
  from `Normal`). `BossOverride(Normal)`/`(Hard)` return the existing bands unchanged — those
  already match the contract exactly.
- Reactions (30–45 / 15–20 / 4–8), block (10/40/80), block-through-hitstun (10/45/85) and DI
  (0/40/80) now follow the tier; every one of those numbers already existed and only needed wiring.
- **HP 700 / 1000 / 1500** from the authored 1000 base with a single application of the scaling.
- **Hard-only purchased-perk mirroring.** `CharacterFactory.CreateCharacter` gained a fourth
  optional parameter `bool applyLegacyUnlockLocks = true`. The mirror calls
  `applyStoryProgression: <isHard>, applyLegacyUnlockLocks: false`. The split was required: F20 wants
  Hard to mirror purchased grid nodes **and** wants core-kit access "independent of Story ability
  locks at encounter time", which the single old switch could not express. Single application of
  stat modifiers is structural — `EncounterMaxHPOverride` *replaces* the baseline in
  `PlayerController.MaximumHP`, so a mirrored `MaxHP` perk can never stack a second base pool.
- **Outgoing campaign damage multiplier wired (this was a real gap).** The clone is a
  `PlayerController` and so never passed through `EnemyAbilityExecutor.DamageMultiplier`; F20's
  0.5×/1.0×/1.5× row was simply not applied to it. `MirrorParadoxController` now multiplies
  `StoryBasicDamageMultiplier` / `StorySpecialDamageMultiplier` (the lanes the basic string
  recomputes every swing and every `BaseSpecial` reads at cast) and scales the handful of
  construction-time ability hitboxes in place. Exactly once, composing with Hard's mirrored damage
  perks.
- `mirror_paradox.tres`'s melee/ranged thresholds and `WeightedRandom` pattern were left as-is, as
  the dossier directs (cosmetic; the mirror carries no `BossAbilities`).

### 1.4 First Unbound Phase 2 self-rewind — T01b Option A (dossier item 4)

New on `BossController`: a lazily allocated **181-sample** position/HP ring recorded once per
authoritative 60 Hz tick (after the rewind-frozen / dead / hitstop early-returns, before status,
cooldown and movement resolution), the exact **180-frame** lookback with an oldest-real-sample
fallback, the contract's `heal = max(0, min(P − H, floor(0.20·M), M − H))`, a three-tier
**historical → current → authored anchor** destination chain with an injectable validator, and a new
`BossState.HistoricalRecovery` (enum appended) whose **90-frame** beat runs before every other clock
on the controller — statuses, the F07 Conductive mark, ability cooldowns, an in-flight hitstop and
the executor all hold their remaining values, and `ApplyBossDamage` refuses damage the way it
already did during `PhaseTransitioning`.

Lethal damage wins for free (`Die()` already runs before `CheckPhaseTransition`), and the
"33% queues P3 even if healing raises HP" rule came free too — the existing `while` loop latches
every threshold crossed in one resolution and reads `CurrentPhase`, never the healed HP. Both are now
pinned.

`BossData` gained additive bool `HasHistoricalRecovery` plus four constants
(`HistoricalRecoveryLookbackFrames` 180, `HistoricalRecoveryHistorySamples` 181,
`HistoricalRecoveryHealCapFraction` 0.20, `HistoricalRecoverySuspendFrames` 90). The cap and the
lookback are global rules, so they are constants rather than a second authored number.

### 1.5 Borrowed Legacies P3 (dossier item 5, plan §2.5)

New `scripts/Enemies/BorrowedLegacies.cs` projects each borrowed character's **Special 1**
`AbilityData` into a runtime `EnemyAbilityData`: archetype by `AbilityExecutionType`
(Projectile → `Projectile`; Area and PersistentObject → `AreaPulse`; else `MeleeStrike`), `Damage`
from `BaseDamage`, `TelegraphFrames` from the authored startup frames, `PresentationEventID` set to
the source's canonical ability ID (the `AbilityVisualLibrary` cradle hook), everything else at the
archetype default. **The roster comes from A5's manifest-backed `CampaignCaptiveRoster` minus the
active hero — never a literal list.**

`BossController` appends the projections to a **runtime composite kit** gated to the boss's *final*
phase (derived from `PhaseCount`, not authored) through the existing `AbilityMinPhase` mechanism.
All projections carry the default `SelectionWeight` of 1, so the existing weighted roll is
weighted-uniform across them. Selection, cooldowns and execution all read the composite through
`ActiveAbilityArray` / `GetActiveAbilityMinPhase` — one kit concept, not two selection paths. The kit
rebuilds only when the locked hero changes.

`archive_remnants.tres` is **retained unchanged** (augment, not replace): changing its
`SummonMinions` archetype would break `EnemyRosterContentTests`' five-boss-summon pin and its
`RosterVfxMap` binding for no behavioural gain, and keeping it guarantees a working P3 attack if the
manifest is unavailable. Its `en.csv` value is already "Borrowed Legacies" (A6), so the authored slot
and the projected set share one name.
