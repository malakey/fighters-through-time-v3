# P12 W3 — Combat data contract (both modes, part 1)

Branch `p12/W3` (from `10c8d6a`, Package 12 Phase 0). Items: M08, M06, M09 pins, block-cancel on Specials, the guard-break push, M01 (D1(a)), M04 (D2(a)). GAP-09 / D14 (the Story hazard block layer) is **held** and was not touched.

## 1. The M08 contract — exact names (W3b and W4 build on these)

### Enums (`scripts/Combat/HitboxSystem.cs`, namespace `FTT.Combat`)

| Enum | Members (ordinal) | Meaning |
|---|---|---|
| `BlockClass` | `Basic = 0`, `Special = 1`, `GuardCrush = 2`, `Unblockable = 3` | How a hit meets the ordinary block: 1 charge / full shatter / 2 charges / bypass |
| `HitDelivery` | `DirectHit = 0`, `Tick = 1`, `Construct = 2`, `Hazard = 3` | Rally reclaim (only `DirectHit` collects), hitstop exemption, absorption |
| `HitOrigin` | `Basic = 0`, `Special = 1`, `Ultimate = 2`, `Throw = 3`, `Environment = 4` | D03h meter rule, origin inheritance |

`AttackClass` (`Basic/Special/Ultimate/Hazard`) is **kept** as the runtime classification the block and hyper-armor code already switch on. It is not a second canonical value: `HitClassification.AttackClassFor(BlockClass, HitOrigin)` is the one mapping (Ultimate origin → `Ultimate`; `BlockClass.Basic` → `Basic`; otherwise `Special`, with GuardCrush riding as Special + `BlockChargeCost = 2`).

### `HitClassification` (static, engine-free)

- `bool CollectsEcho(HitDelivery)` — `DirectHit` only.
- `bool IsUltimateOrigin(HitOrigin)`.
- `AttackClass AttackClassFor(BlockClass, HitOrigin)`.
- `int BlockChargeCostFor(BlockClass)` — 2 for GuardCrush, else 0 (= class default).
- `ulong NextContactId()` — Story-only monotonic per-contact identity (0 = unassigned).

### `AbilityData` (new export group "Hit (M08)")

| Field | Type | Default |
|---|---|---|
| `HitstunFrames` | `int` | 12 |
| `BlockClass` | `BlockClass` | `Special` |
| `Launches` | `bool` | false |
| `Delivery` | `HitDelivery` | `DirectHit` |
| `Origin` | `HitOrigin` | `Special` |

- `HitstunDuration` is **no longer exported**: it is a read-only `=> HitstunFrames / 60f` kept for the kit scripts that build payloads in seconds. There is one canonical value (the frames).
- `ResolvedAttackClass` → `HitClassification.AttackClassFor(BlockClass, Origin)`.

### `HitPayload` additions

`ulong SourceActorId` (Godot instance ID of the owning actor, 0 if unknown), `ulong ContactId`, `bool Launches`, `HitDelivery Delivery`, `HitOrigin Origin`. The older Vector2 field `HitOrigin` (the contact **position**) keeps its name; the enum-typed field is therefore `Origin`. `HitstunDuration` (seconds) stays on the payload — the design's `HitstunFrames` on the payload was not added to avoid a second canonical value in flight.

### `IDamageable` (`FTT.Combat`)

```csharp
public interface IDamageable {
    float TakeDamage(in HitPayload hit);   // returns HP actually dealt
    bool IsAlive { get; }
}
```

Implemented by `PlayerController`, `EnemyController`, `BossController` (each routes to its existing hurtbox handler — the same chokepoint) and by `Hurtbox` (so every `EnvironmentHurtboxAdapter` strike surface inherits it). **Deviation from the GDD sketch:** it returns the HP dealt (`float`) instead of `void`, because Influence, Rally and projectile detonation all read that number. `IStatusEffectTarget` coexists; it does not inherit `IDamageable`.

### `Hitbox`

- New exports `Launches`, `Delivery` (default `DirectHit`), `Origin` (default `Basic`), carried into `CreatePayload`, plus `SourceActorId`.
- `ApplyAbilityHitContract(AbilityData)` — the single place a hitbox copies class, `BlockChargeCost`, `Unblockable` (non-Ultimate `Unblockable` only), hitstun, launch, delivery and origin from an ability. Used by `BaseSpecial.GetOrCreateChildHitbox`, `PlaceholderProjectile.Setup` and `CharacterFactory.MakeHitbox`.
- `OnAreaEntered` stamps a fresh `ContactId`, routes through `IDamageable.TakeDamage`, and credits the owner with `collectsEcho: CollectsEcho(payload.Delivery)` and `ultimateOrigin: IsUltimateOrigin(payload.Origin)`. W1's freeze gate is untouched.

### Slot-derived flags replaced (straight substitutions, behaviour identical)

| Site | Was | Now |
|---|---|---|
| `Hitbox.OnAreaEntered` | `ultimateOrigin: AttackClass == Ultimate` | `IsUltimateOrigin(payload.Origin)`; `collectsEcho` from `Delivery` (was the default `true`) |
| `PlaceholderZone.Setup` | `UltimateOrigin = data.Slot == Ultimate` | `IsUltimateOrigin(data.Origin)` |
| `PlaceholderZone.CreditOwner` | `collectsEcho: false` | `CollectsEcho(TickDelivery)` (`PlaceholderZone.TickDelivery = Tick`) |
| `BaseSpecial` / `PlaceholderProjectile` / `CharacterFactory.MakeHitbox` | `AttackClass = Slot == Ultimate ? Ultimate : Special` | `ApplyAbilityHitContract(data)` |

Not substituted (W4's area, or code-path-derived rather than slot-derived): the nine ultimate scripts' literal `ultimateOrigin: true`, the four construct nodes' literal `collectsEcho: false`, the sim's intent-kind ultimate origin and zone/construct `collectsEcho: false`.

### Basic string, directional strikes, throws (`BasicComboRules`)

- `StringHitLaunches = { false, false, true }` (finisher only); `DirectionalAttackLaunches = true`; `ThrowLaunches = true`. Story's melee hitbox now carries them (`Origin = Basic`, `Delivery = DirectHit`). Lincoln's launching Hit 2 (M07) is W3b's per-profile override.
- **Data only**: nothing reads `Launches` for behaviour yet. Today every hit with a knockback vector still launches (tumble, DI, tech) in both modes. W3b owns the semantics and component 320.

### The 36 `.tres` (authored by `tools/p12_w3_author_hit_fields.py`, idempotent)

Derived from the build's pre-W3 behaviour:

- `HitstunFrames` = old `HitstunDuration × 60`: **12** everywhere except `lincoln_union_indestructible` **30**.
- `BlockClass` = `Unblockable` for the nine Ultimates, `Special` for everything else (the old slot rule).
- `Origin` = `Ultimate` for the nine Ultimates, `Special` otherwise.
- `Delivery` = `Construct` for the four constructs (coil, turret, nest, snare); `Tick` for `einstein_relativity_rift`, `shakespeare_the_tempest` and `cleopatra_sandstorm_vortex` (D03g names every Vortex tick); `DirectHit` for the rest.
- `Launches` = `true` wherever `KnockbackForce` ≠ 0 (22 abilities, all nine Ultimates included), `false` otherwise (14). This preserves today's "every knockback hit launches"; the GDD does not enumerate the launching Specials, so the table is a **proposal for W3b** (ledger `VERIFY-ABILITY-LAUNCHES`).

### Fighter loadout (`scripts/FighterSim/`)

`FighterAbilityHitData` (readonly struct: `HitstunFrames`, `BlockClass`, `Launches`, `Delivery`, `Origin` — enums as int ordinals) and `FighterAbilityLoadout.SpecialOneHit / SpecialTwoHit / UltimateHit / MovementHit`, filled by `FighterLoadoutFactory.HitData(ability, fallback)`. `FighterAbilityHitData.DefaultSpecial` / `DefaultUltimate` feed `FighterAbilityLoadout.Default`. **Loadout only — no component, no snapshot field, no hash change.** The tick does not read it yet: the sim still applies 18 (Special) / 30 (Ultimate) hitstun (ledger `DEFER-SIM-ABILITY-HITSTUN`). W3b will need a path from the tick to these values.

## 2. The other items

- **M06.** `BasicComboRules.CanBlockEscapeHitstun(grounded, blockHeld, tumbling, stringHitOneGate, stanceCanRise)` is the one gate; Story `ProcessStunned` and the sim movement system both call it. A tumbling victim never escapes into the stance; holding Block on ground contact techs. Note: until W3b, every knockback hit is a tumble, so the Block escape currently fires only from zero-knockback hitstun (and after a tech-less landing it no longer fires at all). The Story hit-2 escape pin now uses a zero-knockback hit.
- **Block-cancel on Specials.** Story `ProcessUsingSpecial`: in the Special's `Recovery` phase, grounded Block (outside an Echo Step wind-up) interrupts the cast into `Blocking`; startup/active never cancel; the armed cooldown stands. The sim has no special recovery lock at all, so the stance rises on the next tick — pinned as the parity half. No sim state needed.
- **Guard-break push.** `BasicComboRules.GuardBreakPushX = 2.0`, `GuardBreakPushYDown = -1.0`, `GuardBreakPushSign(defenderX, attackerX, facingRight)`; Story `BlockSystem.GuardBreakPushVelocity` (±120, −60 px/s) is **assigned** (was added) and signed away from the contact origin; the sim's shatter branch uses `FighterDamageRules.GuardBreakPushSign`/`GuardBreakPushX`/`GuardBreakPushYUp`. Unscaled in both. (A block requires the contact in front, so the sim's result equals the old facing-derived push on every reachable input — no hash change.) Quantum Entanglement's blink is unchanged. `DepleteCharges` (no attacker) falls back to backward-from-facing.
- **M01 (D1(a)).** `UniversalMovementRules.TerminalFallSpeed = 20`, `FastFallSpeed = TerminalFallSpeed`. Sim: `FighterMovementSystem.ClampToTerminal` after both gravity integrations (normal and hitstun/daze); fast-fall **snaps** to −20. The CPU pit probe integrates with the same clamp. Story: fast-fall assigns 1200 px/s; the ordinary 600 px/s terminal is unchanged (H-7 deferred).
- **M04 (D2(a)).** Echo Step wind-up and tech stay flags (ledger `DEFER-M04-SUBPHASE-FLAGS`). The missing Story rows were added: Running → Special/Ultimate; Crouching → Blocking/Rolling/Airborne/Special/Ultimate/Movement; Blocking → Airborne. The sim's `allowJump` now excludes only shieldstun (Blocking → Airborne). Attacking → Airborne/Rolling/Ultimate and aerial landing → Idle already worked and are now pinned. The M05 knockdown row is W3b's.
- **M09.** `ApplyStockLoss` now clears `ZoneSpeedBonusFrames` and `FloatFrames`; `FighterCombatSystem.ClearMarkIfRespawning` drops the victim's Conductive mark (component 318) while on the respawn platform or out of stocks (the stock-loss chokepoint has no `Frame`). Cooldowns, Echo Step cooldown and `DefyHistoryUsed` are kept; HP → max, charges full, meter ×0.75 — all pinned.

## 3. Hashes that moved

No golden-hash test exists; the rollback-readiness, per-stage hash and determinism suites all pass on the new build (full run). Deterministic state changes, by cause:

- **M01**: every fast-fall tick (−16 → −20) and every free fall past 20 u/s (≈40 airborne ticks) — affects Open-stage pits and long falls on every stage.
- **M06**: a landed tumble with Block held on the ground (notably the CPU hitstun-defense linger) no longer clears hitstun.
- **M04 sim**: Block + Jump from the stance now jumps.
- **M09**: stock loss with a live zone buff, float window or Conductive mark.
- Guard-break push and the loadout projection: no change.
