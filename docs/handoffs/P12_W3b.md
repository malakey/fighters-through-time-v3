# P12 W3b — Launches and knockdown (both modes, part 2)

Branch `p12/W3b` (from `main` at `4d5d7cb`, the Wave 1 integration). Items: M05 (authored launches, knockdown and get-up), M07 (Lincoln's launching hit 2), the M06 follow-up pins, the generic half of `DEFER-SIM-ABILITY-HITSTUN`, the two new COMBAT_VALIDATION scenarios, and the CPU's input-side DI adjustment.

## 1. What shipped

### M05 — only an authored launcher launches (both modes)

- **Sim.** `FighterDamageRules.ApplyFighterHit` gained `bool launches = true` (last optional parameter). With `launches` the old path runs: `Velocity = (±f, f·vScale)`, `IsGrounded = 0`, the DI stash and `Tumble = 1`. Without it, a **grounded** victim gets grounded knockback — `Velocity.x = ±f`, `Velocity.y = 0`, still grounded, no stash, no tumble — and an **airborne** victim keeps the authored vector with no stash and no tumble (so no DI, no tech, no knockdown on landing).
- **Call sites passing the flag explicitly:** the basic string (`BasicComboRules.StringHitLaunchesFor(profile, step)`), the directional strikes (`DirectionalAttackLaunches`), throws (`ThrowLaunches`), the melee Special/Ultimate intents and Special projectiles (the projected contract, below), constructs and the coil fence (`false`, matching their authored `Launches = false`). Every other site — the bespoke zone pulses/finales, the expiry launches, the coil chain, stage hazards — keeps the default `true`, which agrees with the proposal table because each of those abilities is authored `Launches = true` (hazards author no flag at all; see `VERIFY-ABILITY-LAUNCHES`).
- **Story.** `PlayerController.ResolveHitLaunches(in HitPayload)` (internal static): a player-sourced payload (`AttackerIndex >= 0`) launches only when `hit.Launches`; a non-player source (enemies, bosses, hazards — none author a flag) keeps "any knockback launches". Only a launch stashes DI and sets `_stunTumble`; a non-launcher on a grounded player zeroes `Velocity.Y`.
- **The table** is W3's proposal, applied unchanged (no `.tres` edited): finisher, Up-Attack, Down-Air, throws, and every ability authored `Launches = true` (the 22 with non-zero knockback). `VERIFY-ABILITY-LAUNCHES` stays open for the design ruling.

### M07 — Lincoln's hit 2

`BasicStringProfile.Hit2Launches` (new optional ctor arg `hit2Launches`), set only on `lincoln`. `BasicComboRules.StringHitLaunchesFor(BasicStringProfile, int)` / `(string characterID, int)` is the one lookup; the sim's `ApplyBasicSwing` and Story's `StartComboHit` (`_meleeHitbox.Launches`) both read it. His victim is airborne after hit 2, so it gets DI and landing tech, never the grounded escape. The finisher-separation guarantee is unchanged (and Lincoln's hit 2 → finisher is an airborne follow-up, exempt from the hit-1→hit-2 link guarantee as M07 says).

### M05 — knockdown and get-up

New constants in `BasicComboRules`: `KnockdownFrames = 30`, `NeutralGetUpFrames = 10`, `RollGetUpFrames = 14`, `GetUpNone/Neutral/Roll = 0/1/2`, `GetUpRollInputThreshold = 0.25f`, `SelectGetUp(direction)`, `GetUpFramesFor(kind)`.

Timeline (sim ticks, `L` = the tumble's landing tick):

| Ticks | Phase | Invulnerable | Actions |
|---|---|---|---|
| `L` | missed tech → knockdown starts, hitstun/tumble/stash cleared, body stopped | yes | none |
| `L+1 … L+30` | knockdown (30 frames) | yes (hits, grabs, meter, Rally all refused) | none |
| `L+30` | get-up chosen from the held stick: `\|MoveX\| > 30` → roll that way, else neutral | — | — |
| `L+31 … L+40` / `L+44` | neutral (10, in place) / roll (14 of travel at `MoveSpeed × RollSpeedMultiplier`) | **no** | none |
| next | control returns | — | — |

A hit that stuns during the get-up (or a stock loss / respawn) ends the sub-phase (`FighterKnockdownRules.ClearIfInterrupted`). A roll get-up that leaves ground support ends and the fighter falls. Story mirrors it on `PlayerController` in physics frames (`_knockdownFrames`, `_getUpKind`, `_getUpFrames`, `_getUpDirection`), inside `CharacterState.Stunned`: the missed-tech branch of `ProcessStunned` calls `BeginKnockdown`, `ProcessKnockdown` owns the sub-phase, `ApplyDamage` refuses while `IsKnockedDown`, `ApplyStun` and `CompleteStoryRewind` clear it. Public read-outs: `IsKnockedDown`, `IsInKnockdownOrGetUp`, `GetUpKind`, `KnockdownFramesRemaining`, `GetUpFramesRemaining`.

Presentation (H03 reuse): the knockdown plays `hitstun`, the roll get-up `roll_recovery`, the neutral get-up `idle` — in Story directly, in Fighter through `FighterSimulationDriver.ResolvePresentationAnimation` (and `GetStateLabel` shows "Knocked Down" / "Getting Up").

Level 0's tech lesson and the F18 landing-tech drill needed no change: both already treat "a tumble that ended on the floor without the tech lock" as the miss, and Level 0's miss now fires after the full knockdown plays, exactly as the design asks.

### Component 320 — `FighterKnockdownComponent`

`[KlothoComponent(320, MaxCount = 2)]`, `Pack = 4`:

| Field | Type | Inactive |
|---|---|---|
| `KnockdownFrames` | int | 0 |
| `GetUpKind` | int (`BasicComboRules.GetUp*`) | 0 |
| `GetUpFrames` | int | 0 |
| `GetUpDirection` | int (−1/0/+1) | 0 |

**16 bytes.** Added at spawn (`FighterWorldSystem.SpawnFighter`), cleared at Sudden Death setup, cleared on respawn/out-of-stocks through `ClearIfInterrupted`. Snapshot and hash state through Klotho like every other component (pinned by `TheKnockdownIsRollbackStateAndReplaysBitIdentically`). The knockdown's invulnerability rides the existing `FighterStateComponent.InvulnerabilityFrames` (set to `max(current, 31)` at the landing), so every hit path, grab and pull that already reads that gate is covered with no pipeline special case. The action lock zeroes the tick's `Held/Pressed/ReleasedButtons` in the movement system before the ability, combat and grab systems read them (the countdown system's rule); `MoveX` survives to choose the get-up. 305 and 310 untouched. AGENTS.md's inventory and `ROLLBACK_STATE_CONTRACT.md`'s "Actor state and timing" row record it.

### DEFER-SIM-ABILITY-HITSTUN — generic half closed

`FighterHitContractTable` (sealed class in `FighterSimulationComponents.cs`) holds the two loadouts' projected `FighterAbilityHitData`. `FighterSimulation` builds it from the loadouts and hands it to `FighterCombatSystem(contracts)` and `FighterProjectileSystem(contracts)` — **static configuration like the stage geometry, not a component, not snapshot or hash state**. `FighterCombatSystem.ResolveIntentContract` gives the melee Special/Ultimate intents the authored `HitstunFrames` + `Launches` (the old 18/30 survive only as `LegacySpecialHitstunFrames`/`LegacyUltimateHitstunFrames`, the fallback for a loadout with no projected contract). `FighterProjectileSystem.ResolveProjectileContract` does the same for Special projectiles by the type-ID slot digit. **Every shipped Special is authored 12 frames**, so sim melee-Special and projectile hitstun drops 18 → 12 (and a default-loadout generic Ultimate 30 → 12). The bespoke per-kit pulse constants remain open in the ledger (W4's dispatch code).

### M06 follow-up

With hits 1–2 now grounded knockback, the hit-2 Block escape fires again from ordinary grounded hitstun. Pinned in both modes (`NonLaunchingHitsStayGroundedAndReopenTheHitTwoBlockEscape`, `ANonLaunchingHitIsGroundedKnockbackAndHitTwoReopensTheBlockEscape`). A missed tech's knockdown cannot be Block-escaped either (the W3 case, rewritten in place).

### CPU (input-side only)

`FighterCpuController.ApplyHitstunDefense` holds the DI stick only while `observation.IsGrounded == 0` in hitstun — the input-side read of "launched", since a non-launcher leaves a grounded victim grounded. The Block hold is unchanged, so a defending CPU still takes the hit-2 escape from grounded hitstun and techs a launch. The Easy/Normal/Hard matrix and both sim integrations still pass; the linger needed no retune.

## 4. Not delivered / needs

- `VERIFY-ABILITY-LAUNCHES` stays open: the Specials/Ultimates launch table is W3's proposal, unruled; enemies, bosses and hazards author no flag.
- **Story kit scripts that build their own `HitPayload`** (W4's area) do not stamp `Launches`, so those hits do not tumble a `PlayerController` victim — in shipped Story that is only the Level 13 Mirror Paradox clone. The fix is mechanical (`Launches = Data.Launches`) and belongs with W4's payload pass.
- `VERIFY-M05-KNOCKDOWN-SCOPE` (new): the one-bounce is not a separate phase; Story enemies/bosses have no knockdown (W9's area), so the stagger-accounting and thrown-mob clauses have nothing to attach to.
- `DEFER-SIM-ABILITY-HITSTUN` narrowed, still open: the bespoke per-kit sim hitstun constants.
- Grounded knockback has no friction during hitstun (unchanged from before — launched victims also kept their horizontal speed through hitstun). At the default spawn gap Joan's finisher now whiffs after a two-hit string because the victim has slid ~3 units; this is existing spacing behaviour, not a new rule, and is exactly the F09 question COMBAT_VALIDATION owns.
