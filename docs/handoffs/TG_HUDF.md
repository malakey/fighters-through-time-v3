## Kit gaps and a widget bug (for the orchestrator)

1. **Bug in `PulpAbilitySlot` (TG-WIDGETS' file; both HUDs).** `Relayout` (line 269) reads the slot number's size from the shared theme (`UIPalette.LoadTheme()`), which `UIPalette.ApplyUiScale` rescales; a HUD that scales by transform (`UiScaleBinder`) then scales it again. At UI scale 1.4 the lens's centre number draws about 1.4 x too large (about 38 px against 27): `hudf_140` shows it, because the 1.4 targets now scale the shared theme as Settings does. (Tests and earlier captures never scaled the shared theme, so nothing saw it.) Fix: read the size through the slot's own theme context (for example `GetThemeFontSize("font_size", UIPalette.LabelRoles.SlotNumber)` on the slot, which resolves the HUD's unscaled copy) and re-run on that context's theme change. Not patched here: `scripts/UI/Pulp/` is read-only in Phase B.
2. **Line heights.** The roles carry the faces' natural line boxes (Cinzel 1.348 em, Outfit 1.26 em), not the CSS line-heights, so a container lays a single line out taller than the mock (T09 38 against 28; the lens key label sits 2.3 px lower than the CSS). `spacing_top` / `spacing_bottom` on the roles (T09: -5 / -5) would let containers place them at the spec's boxes; the HUD lays its header out by hand instead.
3. `PulpStatusChip` draws its badge at its rect's top; in a row taller than the badge it needs `ShrinkCenter` (the HUD sets it). The chip could centre itself.
4. No parallelogram form of the not-yet frame for a tube.
5. The Fighter "/max" shares `HudNumeralSmall` (Outfit 600 22) where the spec draws Outfit 400 20.9 (TG-THEME's mapping, noted there).
