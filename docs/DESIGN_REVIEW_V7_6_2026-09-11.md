# Fighters Through Time — V7.6 design review

Review date: September 11, 2026. Baseline: the current working copy of `design-godot-v7.md`, including the V7.6 changes dated September 11.

**Resolution status (2026-09-12):** all numbered findings **F01–F24 are resolved in design** through the user-selected decisions recorded below. Approved changes are reflected in the main document, affected HTML mirrors and linked system contracts. Documentation checks do not constitute runtime, migration, visual or balance sign-off; those checks remain explicitly pending. The additional unnumbered system, theme, genre and scope recommendations later in this review remain separate follow-up work, not silently approved or completed by closing this list.

The game has a coherent central idea: historical legacies become combat powers, and recent time becomes something the player can negotiate. Rally, Echo Step, Stasis Echo, the Erasers, and the shared Story/Fighter kits support that idea. The main problem is now the interaction between systems. The document repeatedly establishes a rule, adds a useful exception elsewhere, and leaves the original rule, its schema, or its tutorial intact.

**Recommendation:** stabilize the timer, retry economy, ability contracts, and progression requirements before adding more systems. Preserve the distinctive HP/platform-fighter hybrid, linear campaign, and time mechanics. They need validation and clearer boundaries more than additional mechanics.

This is a design/specification audit, not a runtime bug report. I reviewed the main document across its 17 sections, checked relevant HTML mirrors, and compared the previous September 8 audit with the new rulings. I did not run the game or validate its implementation claims. At the original audit, declared authorities including `docs/DUST_ECONOMY.md`, `docs/PACKAGE5_CAMPAIGN_PLAN.md`, and `resources/Abilities/` were absent from this checkout. F05 now supplies the economy design ledger; scene reward inventories and the other referenced authorities remain outside this review. Conclusions about those systems concern the supplied specification. The original read-only review left existing edits unchanged; subsequent user-approved document changes are recorded in the resolution notes.

Severity labels: **P1** means resolve before implementation or balance lock; **P2** means resolve before content completion or player-facing validation. “Risk” means the document permits a problematic outcome that needs a rule or playtest; it does not claim the shipped game already exhibits it.

## 1. Highest-priority findings

### F01 — P1: The timer formula and its stated budget do not agree

> **RESOLVED IN DESIGN — user selected Option A (normalize the existing formula).** The main document and Campaign/Architecture HTML now define the all-Extractors-alive budget, entry-to-boss-gate par, fixed initial drain factor, and normalized equation. Existing difficulty multipliers and ending thresholds remain unchanged. A ten-minute par expires after 20 / 15 / 12 live minutes with all machines alive and no secret. Extractors and secrets slow future drain without refilling the gauge. This closes the formula ambiguity; implementation and route/ending balance validation remain outstanding. The original finding below is retained as review history.

The budget is critical-path par time, measured with all Extractors alive, multiplied by difficulty. A separate rule then multiplies drain by `1 + 0.2 × living Extractors − 0.1 × secret found`. The conversion from the authored budget to base drain is missing. [Timer specification](D:/Projects/fighters-through-time-docs-3/design-godot-v7.md:308)

If an implementer uses `baseDrain = 100 / (par × difficultyMultiplier)`, the result at par, with no detours and every Extractor alive, is:

| Extractors | Easy, 2.0× par | Normal, 1.5× par | Hard, 1.2× par |
|---|---:|---:|---:|
| 2 | 30% left | 6.67% left | Collapses before par |
| 3 | 20% left | Collapses before par | Collapses before par |

For example, a ten-minute par with three Extractors on Normal gives a fifteen-minute nominal budget, but the 1.6× drain empties it after 9.375 minutes. That contradicts the stated all-alive budget and makes nominally optional Extractors effectively necessary.

**Recommended clarification:** define par as live gameplay time from entry to the boss gate, excluding the boss and all frozen presentations. Normalize drain against the starting Extractor count:

`drainPerSecond = 100 / (parSeconds × difficultyMultiplier) × currentDrainFactor / initialDrainFactor`

With that interpretation, all-alive clears at par leave 50%, 33.33%, and 16.67% on Easy, Normal, and Hard. That restores the meaning of the budget, but also shows that the fixed 50% good-ending requirement still needs explicit route and difficulty validation. The same ending threshold across difficulties is intentional; its attainability remains unproven.

### F02 — P1 risk: Act III checkpoint deposits reopen unlimited dust farming

> **RESOLVED IN DESIGN — user selected Option A (secure Act III dust only at level completion).** Checkpoint Beacons provide grid purchases and free respec using previously deposited dust only. They cannot deposit or spend the active level's earnings. Completion auto-deposits those earnings once; Restart Level clears undeposited earnings as before. Free respec refunds previously spent deposited dust only. The main document and affected HTML mirrors are aligned. Implementation remains pending; the original finding below is retained as review history.

The Beacon allows depositing at any activated Act III checkpoint. Deposited dust is always safe. Restart Level resets every enemy, Extractor, and pickup but clears only undeposited dust. These rules compose into: earn dust → deposit at Beacon → restart → earn the same rewards again. No completed-level replay is needed. [Beacon and failure rules](D:/Projects/fighters-through-time-docs-3/design-godot-v7.md:273), [Restart Level](D:/Projects/fighters-through-time-docs-3/design-godot-v7.md:3937)

This invalidates the finite-income grid economy and makes restarting a way to refill anchor charges while retaining earnings. It is a new interaction introduced by the Beacon, distinct from the accepted crash/Alt-F4 loophole.

**Recommended fix:** let the Beacon open the grid and respec screen using previously secured dust, but secure the current level's dust only at level completion. If checkpoint deposits are important, persist a reward-claim ledger across restarts so each source can pay only once. Specify how forfeited rewards behave; otherwise that alternative can create permanent income loss. The first option is simpler.

### F03 — P1: “Pool reaches zero” spends the last rewind incorrectly

**Resolution (2026-09-11):** the user chose to replace Manual Rewind with separate, single-player Story **Time Freeze**: five seconds, no charges, long cooldown, invulnerable enemies, escape only. Death-rewind charges now serve automatic death recovery only; the last charge completes its rewind, and collapse requires a later unprevented lethal event with no available charge or Integrity reaching zero. Main rules, Act III, controls, tutorial, difficulty tables, HUD, audio, and HTML mirrors are updated. **RESOLVED IN DESIGN (2026-09-12):** the user confirmed a **45-second cooldown beginning when the freeze ends** and **continued Timeline Integrity drain during the freeze**. All Time Freeze choices for this finding are settled; gameplay implementation and validation remain pending. The original finding below is retained as audit history.

The collapse trigger says the timeline collapses when the rewind pool reaches zero. Manual Rewind spends a charge on commit. Hard starts with one charge. Literally, one legal manual rewind causes immediate collapse, and a death that spends the final charge cannot finish its promised rewind normally. The Act III description repeats the empty-pool condition. [Rewind and collapse](D:/Projects/fighters-through-time-docs-3/design-godot-v7.md:2001), [collapse trigger](D:/Projects/fighters-through-time-docs-3/design-godot-v7.md:2041)

**Recommended rule:** a charge may be spent from 1 to 0 and the rewind completes. Collapse occurs on a subsequent lethal event when no rewind is available, or when Integrity reaches zero. Zero remaining charges is a valid living state. State this once and reference it from the HUD, audio, and Act III rules.

### F04 — P1 risk: Required puzzle verbs can be unavailable

**RESOLVED IN DESIGN — Option A (2026-09-12):** the user selected a puzzle-only Nexus Resonance Source for Level 4A's required Ultimate. It authorizes the actual Ultimate against its puzzle target without filling or spending normal meter, supports retries after failure, and cannot supply combat damage, healing, meter, or rewards. Unsolved checkpoint restoration restores source availability; solved gates latch open and disable it. Main rules, Ultimate activation/controls, and affected HTML mirrors are aligned. Retiring Manual Rewind also retires Stasis Echo: former Echo gates use ordinary resource-free mechanisms, and Time Freeze is never a required puzzle verb. Implementation and validation remain pending. Original observations follow.

Level 4A must require the Movement Ability, both Specials, and an Ultimate set-piece. However, every level starts at zero meter; Ultimate, Defy History, and Echo Step all spend meter, and the new Eraser can drain it. The document supplies no guaranteed replenishment or alternate solution at the mandatory Ultimate gate. A player who spends meter on the preceding fight can reach a progression gate without a way to open it. [Legacy Level](D:/Projects/fighters-through-time-docs-3/design-godot-v7.md:256), [meter rules](D:/Projects/fighters-through-time-docs-3/design-godot-v7.md:1200)

The same problem applies to any required Stasis Echo puzzle after the player's last manual-rewind charge has been spent. Only tutorial rewinds are explicitly exempt from cost. [Manual Rewind](D:/Projects/fighters-through-time-docs-3/design-godot-v7.md:2031)

**Recommended fix:** every mandatory resource-gated puzzle needs a local, repeatable provisioning rule or a non-consuming puzzle interaction. For example, an authored resonance source can enable the Ultimate set-piece inside that room; a puzzle anchor can provide a room-limited Stasis use. Limit the provision to the gate so it cannot become combat farming. Keep the existing no-time-refund rule.

### F05 — P1: The advertised dust totals are already exceeded by guaranteed sources

**RESOLVED IN DESIGN — Option A (2026-09-12):** the user selected keeping the 975-dust grid and rebalancing rewards. The new [economy ledger](D:/Projects/fighters-through-time-docs-3/docs/DUST_ECONOMY.md) budgets 720 required-route base dust plus 280 optional base dust; tier-inclusive ranges are 720–787 and 1,000–1,094 with no losses. Sixteen bosses pay 25 each (400 total); other required sources share 320, and optional sources share 280. Flat enemy/Extractor awards and the every-enemy dust guarantee are superseded by fixed authored allocations. The ledger includes all 4A variants, difficulty normalization, source claims/retries, one-time tier bonuses, banking, and upgrade pacing. Main rules and affected HTML mirrors are aligned. Arithmetic is verified; actual scene manifests, runtime changes, and playtesting remain pending. Original observations below are retained as audit history.

The full grid costs 975 dust. Critical-path income is targeted at 700–800; thorough income at 1,000–1,100. Bosses award 50 each, and the Legacy Level adds a sixteenth boss encounter to a playthrough. **Sixteen bosses alone award 800**, before mandatory mobs, the Legacy Eraser, Act III ambushes, or tier bonuses. [Currency and target](D:/Projects/fighters-through-time-docs-3/design-godot-v7.md:438), [economy target](D:/Projects/fighters-through-time-docs-3/design-godot-v7.md:506)

A conservative thorough-route calculation is worse: Levels 2–12 plus 4A are twelve timed pre-Act-III levels. At two Extractors per level and 25 dust each, those add 600. Bosses plus just those Extractors already total **1,400**, before ordinary enemies, secrets, or Act III rewards. This calculation assumes successful collection with no penalties and uses design values; the current 15-dust implementation exception is explicitly provisional.

The document acknowledges a deferred rebalance, so this is **known unfinished work with a demonstrated contradiction**, not an overlooked absence. The new topology does not preserve choice pressure merely by preserving node count.

**Recommended fix:** reconcile the per-level ledger before tuning perk prices. Include guaranteed versus optional encounters, difficulty-dependent enemy counts, secret rewards, 4A variants, bonuses, and retry behavior. Establish when the first Major and second Major should become affordable, not only the final campaign total.

### F09 — P1: Combat safety claims are stronger than the specified rules support

> **RESOLVED IN DESIGN — user selected Option A (retain current combat rules and validate).** Zero landing lag, shieldstun timings, current escape tools, and the separation of PvP from Enemy Stagger Discipline remain. Main and Gameplay/Fighter mirrors now withdraw guaranteed block advantage, hitstop-as-whiff-commitment, and universal loop-escape claims, including the earlier CPU rationale. Block-cancel eligibility explicitly requires usable charges and no conflicting action lock. [The combat validation contract](D:/Projects/fighters-through-time-docs-3/docs/COMBAT_VALIDATION.md) specifies action-dependent block advantage, a pending outcome table, deterministic escape checks, and coverage for aerials, zero-charge defense, walls/ceilings, control statuses, and constructs. All runtime outcome cells remain pending; this resolves the specification claim, not combat balance. The original finding below is retained as review history.

Three claims need correction or proof:

1. Eight frames of shieldstun do not inherently mean the attacker recovers first. Advantage depends on the remaining active/recovery frames at contact and permitted cancels. The aerial section even describes a defender advantage. Produce an on-block outcome table rather than asserting a universal turn order.
2. Hitstop cannot compensate for aerial **whiff** commitment: it only happens on a hit. Landing cancels startup, active frames, and recovery with zero landing lag. This may be an intentional arcade choice, but its stated balancing explanation is incorrect.
3. DI, landing tech, and hit-2 block escape do not prove that every damaging loop is escapable. Grounded shield escape is unavailable without charges; the first charge returns eight seconds after shatter. DI applies to launching hits, and landing tech requires landing. Repeated nonlaunching hits, airborne pressure, and control-status sequences need separate validation.

[Aerial commitment](D:/Projects/fighters-through-time-docs-3/design-godot-v7.md:1040), [hitstop](D:/Projects/fighters-through-time-docs-3/design-godot-v7.md:991), [shieldstun and lockout](D:/Projects/fighters-through-time-docs-3/design-godot-v7.md:1357), [no-juggle policy](D:/Projects/fighters-through-time-docs-3/design-godot-v7.md:1438)

**Recommended action:** retain the intentional no-landing-lag model for the first test. Validate late landing down-airs, repeated launchers at walls/ceilings, zero-charge defense, Root/Static Charge pressure, and construct-assisted sequences. Only adjust commitment or escapes after those scenarios establish the actual problem.

F11 now defines route-based recovery minima (actual route/scoring validation pending); F12 now specifies Entry/PreBoss roles for 4A (actual scene mappings and migration validation pending). Documentation checks passed; implementation, migrations and runtime/crash validation remain pending. The original finding below is retained as review history.

The Story save table contains checkpoint Integrity but no explicit anchor-charge count, Smothered state, Story Defy-used flag, Extractor/secret state, Font/Feast use state, checkpoint-mending use state, or reward-claim ledger. [Save schema](D:/Projects/fighters-through-time-docs-3/design-godot-v7.md:2079), [global dialogue tracking](D:/Projects/fighters-through-time-docs-3/design-godot-v7.md:4035)

**Recommended fix:** define three separate boundaries: fresh attempt, checkpoint resume, and level completion. For every persistent field, state its save trigger and reset boundary. Saving gameplay effects must be independent of whether dialogue is watched. Test transactions around deposits, boss rewards, anchor consumption, and level transitions.
